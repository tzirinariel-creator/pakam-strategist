## 0. המסקנה בפסקה אחת

הקו העיצובי (`docs/קו-עיצובי.md`) מצוין ועדכני. הבעיה **אינה** השפה — היא ש**הקוד לא מיישם את השפה שלו עצמו** בעקביות, ובמובייל חסרות שכבות־יסוד (safe-area, gutter אחיד, קצב־ריווח). לכן **הכיוון: לחדד ולאכוף את השפה הקיימת (אינדיגו/זהב/מלך), לא לזרוק אותה.** הוכחה: כשמכסים את הלוגו בדשבורד — עדיין מזהים "פכמון" (מבחן 5 של הקו). מה שמרגיש "מיושן" הוא סחף: כותרות מיד־חופשית, spinners אפורים ישנים, `space-y-8`, ריווח כפול במובייל, כרטיסי `p-8`. כל אלה נקודתיים ובני־תיקון.

**החלטת מובייל־ראשון:** האפליקציה מתקינה למסך־הבית של iOS (`appleWebApp.capable: true`) אבל **לא קוראת אף safe-area inset ואין `viewportFit: "cover"`** — זה התיקון בעל ההשפעה הגבוהה ביותר. אחריו: gutter אחיד אחד, קצב־ריווח הדוק יותר, וכותרת עמוד אחת (`PageHeader`) בכל מסך.

## 2. הכיוון — "לחדד ולאכוף", עם 5 מערכות מוחשיות

### 2.1 מערכת ריווח (spacing) — gutter אחד, קצב אחד
**החלטה:** ה־gutter של העמוד נקבע **פעם אחת** בשל, ותוכן־העמוד **אף פעם לא מוסיף `p-*` משלו** — רק `gap`/`space-y` בין בלוקים.

- `protected-shell.tsx`: `p-2 sm:p-4 md:p-6` → **`px-4 py-4 md:px-6 md:py-6`** (gutter אחיד 16px במובייל, 24px בדסקטופ; מבטל את ה־`p-2`).
- כל content-root (planner/record/graduation/settings/catalog/exam-planner/calendar/guide): **להסיר** את `p-4 md:p-6` / `p-6` / `p-8` מה־div החיצוני; להשאיר רק `flex flex-col gap-5` (או `space-y-5`).
- קצב קנוני לאכוף: בלוקים `gap-5` (להחליף כל `space-y-8`/`space-y-6`), בתוך כרטיס `p-4` (פאנל ראשי `p-5`), רשימה `space-y-2`.

### 2.2 מערכת מובייל (safe-area + one-hand)
**החלטה:** לאמץ safe-area insets גלובלית, ולהצמיד ניווט/FAB לתחתית הבטוחה.

- `layout.tsx` viewport: להוסיף `viewportFit: "cover"`.
- `globals.css`: להוסיף משתני־נוחות:
  ```css
  :root {
    --safe-top: env(safe-area-inset-top, 0px);
    --safe-bottom: env(safe-area-inset-bottom, 0px);
    --nav-height: 4rem; /* h-16 */
  }
  ```
- `mobile-nav.tsx` (bottom nav): הגובה נשאר `h-16` אבל מוסיפים `pb-[var(--safe-bottom)]` והגובה־האפקטיבי `h-[calc(4rem+var(--safe-bottom))]`; הדראוור `bottom-16` → `bottom-[calc(4rem+var(--safe-bottom))]`.
- `protected-shell.tsx`: `pb-20` → `pb-[calc(5rem+var(--safe-bottom))] md:pb-0` — כדי שהתוכן לא ייחתך מאחורי הנאב.
- `floating-assistant.tsx` FAB: `bottom-20` → `bottom-[calc(5rem+var(--safe-bottom))]`; ה־bottom-sheet `bottom-0` → מוסיפים `pb-[var(--safe-bottom)]` בתחתית אזור־הקלט.
- **one-hand reach:** הפעולה הראשית של כל מסך (CTA האינדיגו) כבר קרובה לתחתית ב־hero; ודאו שכל CTA ראשי במובייל אינו בקצה־העליון בלבד. FAB ב־`end-4` (אגודל) — נכון, לא לגעת.

### 2.3 מערכת כותרות — `PageHeader` בכל מסך
**החלטה:** `PageHeader` היא כותרת־העמוד היחידה. אפס H1 ביד־חופשית.

- להמיר ל־`PageHeader`: dashboard, planner, record, graduation, regulations, settings, catalog, exam-planner, calendar, guide (כל מי שעדיין מצייר `<h1>` בעצמו).
- דשבורד: ה־`title` = הברכה האישית ("היי דני"); ה־`subtitle` = "פכ״מ · סמסטר א׳ · שנה 2"; ה־`actions` = כפתור פתיחת הסיור. (זה מה שהקו כבר מתאר במפורש בתבנית #1.)
- מתכנן: `icon={GraduationCap}`, `title={t("title")}`, `subtitle={t("dragHint")}`, `actions` = תג־תקנון + שיתוף + "שנה תכנון סמסטר".

### 2.4 מערכת טעינה — `ThemedLoader` בלבד
**החלטה:** להרוג את שלושת ה־spinners האפורים.

- `dashboard/page.tsx` `DashboardFallback` → `<ThemedLoader />`.
- `dashboard-content.tsx:117-148` (`PostOnboardingTransition` הפעיל) → להחליף את ה־`border-4 border-foreground/10 border-t-foreground/60` ב־`ThemedLoader` (עם בר־ההתקדמות שנשאר מתחתיו). ה־`exhausted` state כבר בסדר (אייקון בכובע).
- `study-planner-widget.tsx` spinner → skeleton בגריד הסופי (או `ThemedLoader variant="inline"`).

### 2.5 מערכת צבע — לרסן את פלטת ה־-500/10
**החלטה:** ה־QuickActionCards ותגי־ה־GPA לא ישתמשו בפלטה צבעונית מלאה (emerald/violet/amber/orange). כל צ'יפ־אייקון של פעולה → **אינדיגו־muted** (`bg-accent-brand-muted text-accent-brand`), כמו צ'יפ הכותרת. סטטוס (ירוק/ענבר/אדום) נשאר רק למשמעות־סטטוס אמיתית, לא לקישוט אייקונים. זה מיישר את "אינדיגו = הקול" ומרגיע את הרעש.
- `dashboard-content.tsx` QuickActionCard: להסיר את שדה ה־`color` הצבעוני; אחיד אינדיגו-muted.
- תג־GPA ב־`my-status-hero.tsx:57-67` — לשמור (ירוק/ענבר כאן = סטטוס אמיתי מול הסף, מותר).

## 4. מובייל — כללים + המסכים הכי גרועים לתקן ראשונים

### כללי־מובייל לאכיפה (מוסיפים כמדור ל־`docs/קו-עיצובי.md`)
1. **safe-area תמיד**: כל אלמנט `fixed` צמוד־תחתית קורא `var(--safe-bottom)`; כל אלמנט צמוד־עליון קורא `var(--safe-top)`.
2. **gutter אחד**: 16px במובייל (`px-4`), 24px בדסקטופ (`md:px-6`) — מהשל בלבד. תוכן־עמוד לא מוסיף gutter.
3. **קצב הדוק**: בין בלוקים `gap-5` (לא `space-y-8`); בתוך כרטיס `p-4`.
4. **יעד־מגע ≥44px**; פעולות־שורה תמיד גלויות במובייל (לא רק ב־hover) — כבר נכון ברוב המקומות, לאמת.
5. **טור־טקסט לא ארוך**: פסקאות־מובייל עד ~2 שורות; מעבר לזה — לקצר קופי או לפרוס לאקורדיון. (record/graduation הם החשודים.)
6. **CTA ראשי בהישג־אגודל**: קרוב לתחתית, לא רק בקצה־עליון.

### 3 המסכים הגרועים ביותר לתקן ראשון
1. **record (`academic-record-content.tsx`)** — `space-y-8` + כרטיסי `p-6`/`p-8` + H1 `text-3xl` + טורי־טקסט ארוכים. הכי "ארוך וצפוף" במובייל. תיקון: gutter מהשל, `gap-5`, כרטיסים ל־`p-4`, `PageHeader`.
2. **dashboard (`dashboard-content.tsx`)** — `space-y-8`, H1 `md:text-3xl`, ריווח כפול, פלטת -500/10 בפעולות. הכי־נצפה. תיקון: כל עדיפות 1+2 חלים כאן.
3. **planner (`planner-content.tsx`)** — H1 ביד־חופשית בלי צ'יפ, ריווח כפול. תיקון: `PageHeader` + הסרת `p-4 md:p-6` מה־root.

## לאריאל — בעברית פשוטה

בדקתי את כל המסכים מול מסמך־היסוד העיצובי שלך. החדשות הטובות: **השפה העיצובית עצמה מצוינת ולא צריך לזרוק אותה** — אינדיגו/זהב/מלך עובד, וכשמכסים את הלוגו עדיין מזהים שזה פכמון. מה ש"מרגיש מיושן" זה שהקוד לא תמיד מציית לחוקים של עצמו: כותרות שכל מסך מצייר אחרת, שלושה ספינרים אפורים ישנים, וריווח כפול שדוחק הכל במובייל.

הכי חשוב וגם הכי משתלם: **המובייל שבור בשכבת־היסוד** — האפליקציה מותקנת למסך־הבית של האייפון, אבל אף אחד לא לוקח בחשבון את הפס־התחתון (home indicator), אז תוכן וכפתורים מסתתרים מאחוריו, ויש ריווח כפול שגורם לתחושת צפיפות ואורך. זה תיקון קטן־יחסית עם השפעה ענקית.

ההמלצה שלי בשורה: **לחדד ולאכוף, לא לעצב מחדש.** שלושה גלים — קודם יסוד־מובייל (safe-area + gutter אחד), אחר כך קצב־ריווח וכותרת אחידה בכל מסך, ואז ליטוש (להרוג ספינרים אפורים, לרסן צבעים מיותרים). המסכים לתקן ראשונים: **הרשומה האקדמית (record), הבית, והמתכנן** — בדיוק שלושת אלה שהרגשת שצפופים/ארוכים במובייל. אין פה החלטת־טעם פתוחה שדורשת ממך לבחור — הכל נגזר מהקו שכבר כתבת; רק צריך לבצע.
