## ההחלטות (רשימה סגורה)

1. **‎/shared-plan הופך לציבורי** — התיקייה עוברת מ-`(protected)` ל-`(public)` (ה-URL לא משתנה — route groups לא משנים נתיב), ו-`shared-plan` מתווסף ל-`PUBLIC_SEGMENTS` ב-middleware.
2. **מה נחשף בעמוד המשותף:** שמות-קורסים, שנה/סמסטר, ש״ס לקורס וסך-ש״ס. **מה לעולם לא:** ציונים, סטטוסים, אימייל, שם-משפחה, מזהי-משתמש. הטוקן ממשיך להכיל רק `{c,y,s}` — ועכשיו גם `n` (שם פרטי) **רק בהסכמה מפורשת**.
3. **טוקן v2, בטוח ל-UTF-8, תואם-אחורה:** `encodePlan` מקבל שם אופציונלי; `decodePlan` מחזיר `{ courses, name? }` ומקבל גם טוקני v1 ישנים (קישורים שכבר נשלחו לא נשברים).
4. **הסכמה = צ'קבוקס כבוי-כברירת-מחדל** בדיאלוג-שיתוף חדש במתכנן: "לצרף את השם הפרטי שלי". בלי צ'קבוקס — אין שם בקישור. אין שם-משפחה לעולם.
5. **דיאלוג-השיתוף** (Radix Dialog בפורטל, לפי הקנון) מציג בדיוק מה החבר יראה ומה לא, ונותן שתי פעולות: "העתקת קישור" (ראשי, אינדיגו) ו"שליחה בוואטסאפ" (משני). זה סוגר גם את שיתוף-התוכנית-לוואטסאפ.
6. **CTA למבקר לא-מחובר:** במקום כפתור-הייבוא — כפתור אינדיגו "רוצה לתכנן ככה את התואר? הצטרפות לפכמון" → ‎/signup, ושורת-משנה "כבר רשומים? התחברות" → ‎/login. לפני הניווט נשמר נתיב-חזרה ב-localStorage (נתיב יחסי בלבד, תוקף 24 שעות) — ואחרי login/signup חוזרים לעמוד המשותף. משתמש מחובר רואה את כפתור-הייבוא הקיים ללא שינוי.
7. **OG דינמי:** ‎`/api/og/shared-plan?d=<token>` עם `ImageResponse`; מציג "X קורסים · Y סמסטרים" + "התוכנית של {שם}" אם יש שם. **בלי ש״ס ב-OG** (אין DB בראוט — לא מציגים מספר שאיננו ודאי). פונט Rubik נטען בזמן-ריצה מ-Google Fonts עם cache; כל כשל → redirect ל-`/og-image.png` הסטטי. העמוד מקבל `robots: noindex` (קישורי-שיתוף לא נכנסים לגוגל).
8. **"שתף את השבוע שלי" = טקסט לוואטסאפ, לא תמונה.** פונקציה טהורה `buildWeekShareText` + כפתור בשורת-הפעולות של היומן (לצד ייצוא-ICS), פותח `wa.me/?text=…`. ההודעה מסתיימת בקישור לנחיתה — הלולאה הוויראלית השנייה.
9. **הצעד-החברתי אחרי 40 משתמשים = "דופק המחזור"** — שורת-ספירה אנונימית אחת ("N מהמחזור שלך מתכננים את הקורס") מנתוני UserCourse הקיימים, k≥5, מאחורי דגל. **מפרט בלבד — לא נבנה עכשיו** (סעיף ג' למטה).
10. **אפס שינויי-DB ואפס מיגרציות בגל הזה.** הכול client-side / publicProcedure קיים.
11. חריגת-hex מותרת אחת: בראוט ה-OG (satori לא רואה את globals.css) — עם הערה שמפנה לטוקנים.

#### צעד 2: טוקן v2 — `src/lib/plan-share.ts` (החלפת הקובץ)
```ts
export interface SharedCourse { c: string; y: number; s: "FALL" | "SPRING" | "SUMMER" }
export interface SharedPlan { courses: SharedCourse[]; /** first name, consent-only */ name?: string }

// UTF-8-safe base64 (btoa is Latin-1 only — a Hebrew name would throw).
function toBase64(s: string): string {
  const bytes = new TextEncoder().encode(s);
  if (typeof btoa !== "undefined") {
    let bin = "";
    for (const b of bytes) bin += String.fromCharCode(b);
    return btoa(bin);
  }
  return Buffer.from(bytes).toString("base64");
}
function fromBase64(s: string): string {
  if (typeof atob !== "undefined") {
    const bin = atob(s);
    return new TextDecoder().decode(Uint8Array.from(bin, (ch) => ch.charCodeAt(0)));
  }
  return Buffer.from(s, "base64").toString("utf8");
}

export function encodePlan(courses: SharedCourse[], name?: string): string {
  const trimmed = name?.trim().slice(0, 30);
  const json = JSON.stringify({ v: 2, c: courses, ...(trimmed ? { n: trimmed } : {}) });
  return toBase64(json).replace(/\+/g, "-").replace(/\//g, "_").replace(/=+$/, "");
}

/** Accepts v1 ({v:1,c}) and v2 ({v:2,c,n}) tokens. Never throws. */
export function decodePlan(token: string): SharedPlan | null {
  try {
    const obj = JSON.parse(fromBase64(token.replace(/-/g, "+").replace(/_/g, "/"))) as
      { v?: number; c?: unknown; n?: unknown };
    if (!obj || !Array.isArray(obj.c)) return null;
    const out: SharedCourse[] = [];
    for (const x of obj.c as unknown[]) {
      const r = x as Record<string, unknown>;
      if (typeof r.c === "string" && typeof r.y === "number" &&
          (r.s === "FALL" || r.s === "SPRING" || r.s === "SUMMER"))
        out.push({ c: r.c, y: r.y, s: r.s });
    }
    if (out.length === 0) return null;
    const name = typeof obj.n === "string" && obj.n.trim() ? obj.n.trim().slice(0, 30) : undefined;
    return { courses: out, name };
  } catch { return null; }
}

// ---- return-after-auth (viral loop closure) ----
const RETURN_KEY = "pakamon.shared-plan-return";
export function rememberSharedPlanReturn(): void {
  try {
    const path = window.location.pathname + window.location.search;
    if (!path.startsWith("/")) return; // relative path only — no open-redirect
    localStorage.setItem(RETURN_KEY, JSON.stringify({ path, ts: Date.now() }));
  } catch { /* storage blocked — CTA still works, just no return */ }
}
export function consumeSharedPlanReturn(): string | null {
  try {
    const raw = localStorage.getItem(RETURN_KEY);
    localStorage.removeItem(RETURN_KEY);
    if (!raw) return null;
    const { path, ts } = JSON.parse(raw) as { path?: string; ts?: number };
    if (typeof path !== "string" || !path.startsWith("/") || path.startsWith("//")) return null;
    if (typeof ts !== "number" || Date.now() - ts > 24 * 60 * 60 * 1000) return null;
    return path;
  } catch { return null; }
}
```

```ts
import type { ScheduleSessionData } from "@/components/calendar/weekly-timetable";

const DAY_ORDER = ["SUNDAY","MONDAY","TUESDAY","WEDNESDAY","THURSDAY","FRIDAY","SATURDAY"] as const;
const DAY_HE: Record<string,string> = { SUNDAY:"יום א׳", MONDAY:"יום ב׳", TUESDAY:"יום ג׳",
  WEDNESDAY:"יום ד׳", THURSDAY:"יום ה׳", FRIDAY:"יום ו׳", SATURDAY:"שבת" };
const TYPE_HE: Record<string,string> = { lecture:"הרצאה", tutorial:"תרגול", lab:"מעבדה" };

export function buildWeekShareText(
  sessions: ScheduleSessionData[],
  opts: { semesterLabel: string; appUrl: string; isHe: boolean },
): string {
  const { semesterLabel, appUrl, isHe } = opts;
  const byDay = new Map<string, ScheduleSessionData[]>();
  for (const s of sessions) (byDay.get(s.dayOfWeek) ?? byDay.set(s.dayOfWeek, []).get(s.dayOfWeek)!).push(s);
  const lines: string[] = [isHe ? `המערכת שלי — ${semesterLabel}` : `My timetable — ${semesterLabel}`, ""];
  for (const day of DAY_ORDER) {
    const list = byDay.get(day);
    if (!list?.length) continue;
    lines.push(isHe ? `${DAY_HE[day]}:` : `${day.charAt(0) + day.slice(1).toLowerCase()}:`);
    for (const s of [...list].sort((a, b) => a.startTime.localeCompare(b.startTime))) {
      const name = isHe ? s.course.nameHe : (s.course.nameEn ?? s.course.nameHe);
      const type = isHe ? (TYPE_HE[s.sessionType] ?? "") : s.sessionType;
      lines.push(`${s.startTime}-${s.endTime} ${name}${type ? ` (${type})` : ""}`);
    }
    lines.push("");
  }
  lines.push(isHe ? `נבנה עם פכמון: ${appUrl}` : `Built with Pakamon: ${appUrl}`);
  return lines.join("\n");
}
```

## סיכונים ונקודות-שבירה

1. **btoa-על-עברית הוא מוקש חם:** אם מוסיפים את השם לטוקן בלי החלפת ה-encoding בצעד 2 — כפתור-השיתוף קורס לכל מי שסימן את הצ'קבוקס. צעד 2 חייב להיכנס לפני צעד 6, והבדיקה #1 היא השומרת.
2. **שינוי-חתימה של `decodePlan`** (מערך → אובייקט) שובר בקומפילציה את `shared-plan-content.tsx` ואת הבדיקות הישנות — לתקן את כל אתרי-הקריאה באותו קומיט; `tsc --noEmit` יתפוס כל שכחה.

4. **RTL בסאטורי מוגבל:** אם באימות הידני "28 קורסים · 6 סמסטרים" מתרנדר בסדר שגוי — לפצל לשני צמתים נפרדים בשורה עם `display:flex; flexDirection:"row-reverse"`. לא לשחרר OG עם מספר שנראה הפוך (מספר לא-כן שורף אמון).

## ליקויים (חמור → קל)

**1. [חמור — באג בקוד המפרט עצמו] כפל-קידומת-locale שובר את לולאת-החזרה — בדיוק הפיצ'ר המרכזי.**
`rememberSharedPlanReturn` שומר את `window.location.pathname` — שכולל תמיד את ה-locale (`/he/shared-plan?d=…`; `defineRouting` ב-`src/i18n/routing.ts` בלי `localePrefix`, כלומר ברירת-המחדל "always"). אבל login-form ו-signup-form משתמשים ב-`useRouter` של **next-intl** (`src/components/auth/login-form.tsx:5`, `signup-form.tsx:5` — `from "@/i18n/navigation"`), שמוסיף קידומת-locale לכל push. התוצאה: `router.push("/he/shared-plan?d=…")` → `/he/he/shared-plan` → 404. תרחיש-כישלון: חבר לוחץ "כבר רשומים? התחברות", מתחבר — ומקבל 404 במקום את התוכנית. הבדיקה הידנית #2 הייתה תופסת את זה, אבל המפרט מגיש קוד "מוכן-להדבקה" שגוי.
**תיקון:** ב-`rememberSharedPlanReturn` לקלף את סגמנט-ה-locale לפני השמירה: `const path = window.location.pathname.replace(/^\/(he|en)(?=\/|$)/, "") + window.location.search;` — או פשוט לשמור רק את הטוקן ולשחזר `/shared-plan?d=${token}`. לעדכן גם את בדיקת-היחידה #6 שתכסה בדיוק את זה.

**2. [חמור — הבטחה שלא מתקיימת] לולאת-החזרה לא עובדת בשני מסלולי-ההצטרפות הסבירים ביותר.**
המפרט מכריז "אחרי login/signup חוזרים לעמוד המשותף", אבל: (א) התחברות/הרשמה עם **Google OAuth** עוברת דרך `redirectTo=…?next=/${locale}/dashboard` (login:68, signup:113) — שהמפרט אוסר במפורש לגעת בהם — כך שה-localStorage לעולם לא נצרך; (ב) הרשמה במייל עם **אימות-מייל נדרש** (`signup-form.tsx:168-171`, ענף `confirmationSent`) חוזרת דרך `emailRedirectTo` (שורה 148) ישר לדשבורד — שוב בלי צריכה. שורה 166 שהמפרט מתקן רצה רק כשאימות-מייל כבוי. חבר חדש שקיבל קישור כנראה יירשם עם Google — והלולאה לא תיסגר.
**תיקון מינימלי בלי לגעת ב-OAuth:** לצרוך את המפתח בצד-הלקוח של הדשבורד (hook קטן ב-dashboard-content: אם `consumeSharedPlanReturn()` מחזיר נתיב — `router.replace` אליו). זה סוגר את כל המסלולים בנקודה אחת, והתיקון בטפסים מתייתר. לחלופין: לכתוב במפורש בהחלטה 6 שהלולאה נסגרת רק במייל+סיסמה — אבל אז ההבטחה "הלולאה הוויראלית נסגרת" מוגזמת.

**3. [בינוני — Opus ייתקע] סביבת-הבדיקות היא node, לא jsdom.**
`vitest.config.ts:6` — `environment: "node"`. בדיקות `consumeSharedPlanReturn` (localStorage, window.location) והערת-המפרט "(jsdom + localStorage מדומה)" לא יעבדו כמות-שהן; אין `window` בכלל. jsdom מותקן (package.json:72) אבל לא מחובר.
**תיקון:** לציין במפרט-הבדיקות: קובץ בדיקה נפרד עם פראגמה `// @vitest-environment jsdom` בראשו (או `vi.stubGlobal`). בלי זה — סבב כישלון-ניחוש מיותר.

**4. [בינוני — טענת "מצב קיים" שגויה] "הדמו תמיד נוחת בדשבורד עם reset" — לא נכון לחצי מהמקרים.**
נכון ל-login-form:159 (`/dashboard?reset=demo`), אבל כפתור-הדמו ב-**signup-form** (שורה ~95) עושה `router.push("/planner")` — בלי reset בכלל. הטענה במפרט שגויה עובדתית, וגם חושפת אי-עקביות קיימת (דמו מ-signup לא מתאפס — סתירה לנוהל "reset בכל כניסת-דמו").
**תיקון:** לתקן את הניסוח ל"דמו של login נוחת בדשבורד עם reset; דמו של signup נוחת ב-planner בלי reset — לא נוגעים בשניהם". את אי-העקביות עצמה לתעד כליקוי נפרד, לא לתקן בגל הזה.

**5. [בינוני — עמימות שתגרום לסטייה] "הקנון: rounded-2xl … כמו course-detail-modal" — הקוד לא תואם לקנון.**
`course-detail-modal.tsx:69` משתמש ב-`DialogContent` הדיפולטי, שהוא `rounded-lg` (`src/components/ui/dialog.tsx:64`). קו-עיצובי.md:107 אכן אומר rounded-2xl — כלומר יש סתירה קיימת בין המסמך לקוד, והמפרט מצטט אותה כאילו היא עובדה בקוד. Opus שיעתיק את course-detail-modal יקבל rounded-lg; Opus שיציית למפרט יוסיף override שיהיה שונה מהמודאל-הקנוני.
**תיקון:** לקבוע חד-משמעית: "להשתמש ב-DialogContent כמו course-detail-modal, בלי overrides של עיגול" (עקביות-קוד גוברת), ולהוריד את "rounded-2xl" מהמפרט.

**6. [קל-בינוני] ראוט-ה-OG שומר rejection לנצח.**
`fontPromise ??= …` — אם ה-fetch הראשון לגוגל נכשל (cold start, רשת), ההבטחה הדחויה נשמרת וכל בקשות-ה-OG של אותו instance ייפלו ל-fallback עד מיחזור. **תיקון:** לאפס `fontPromise = null` בכשל (בתוך ה-catch של loadRubik או של GET).

**7. [קל] `TYPE_HE[s.sessionType]` בלי נירמול-רישיות.**
`schedule.ts:90` עושה `.toLowerCase()` הגנתי על sessionType — רמז שהערכים ב-DB לא מובטחים-lowercase. ההודעה תשמיט בשקט את סוג-השיעור. **תיקון:** `TYPE_HE[s.sessionType.toLowerCase()]` (וכך גם באנגלית).

**8. [קל — דיוק ציטוט] "?next= נדחתה במפורש" — לא מדויק.**
תוכנית-סיום:25 אומרת "נדחו מהלילה במפורש (בקצוות התוכנית, **לא נעלמו**)" — נדחה-לעתיד, לא נפסל. המנגנון הצר של המפרט לא סותר את המסמך, אבל הנימוק כפי שנוסח כן מסלף אותו. **תיקון:** לנסח "נדחה לשלב מאוחר יותר; כאן מנגנון צר וייעודי בלבד".

**9. [קל — כנות-כיסוי] "עונה בדיוק על #3 ו-#16" — הגזמה.**
הערות-סיכום-אריאל.md:20 כוללת גם "המלצות לקורסי-בחירה מבוססות-אנשים" ו"לראות ממוצע-אמיתי" — המפרט לא נוגע בהן ולא מכריז עליהן כמחוץ-לתכולה. בנוסף, שורה 74 שם מייעדת את הכרעות נושא-III ליום-5 **עם אריאל** — חלק ג' אמנם owner-gated (טוב), אבל המפרט צריך שורת "מה מההערות נשאר פתוח ליום-5" כדי שאף אחד לא יסמן את הנושא כ"בוצע". **תיקון:** להוסיף סעיף "כיסוי-הערות: מכוסה / מוכרע-בהמתנה / נשאר לישיבת-owner".

**זחילת-scope — מה אפשר למחוק בלי לפגוע בהערות של אריאל:** (א) **צעד 7 (OG דינמי) כולו** — לא מופיע לא בהערות 3/16 ולא ביום-2 של תוכנית-הסיום; הוא גם החלק המסוכן ביותר (פונט מרשת, RTL בסאטורי, חריגת-hex, משטח ציבורי חדש). ה-og-image.png הסטטי כבר נותן קלף-שיתוף סביר. (ב) **שם-בטוקן (החלטות 2-4)** — הלולאה הוויראלית עובדת בלי שם; מחיקתו מוחקת את רוב שטח-הפרטיות, את הצ'קבוקס ואת חצי מסיבוכיות v2 (את תיקון-ה-btoa כדאי להשאיר כחיסון). שני אלה יחד הם ~40% מהמפרט ו-0% מההערות.

**סגירות-החלטות:** טובה. לא מצאתי "או"/"כדאי לשקול" אמיתיים; שני התנאים שנותרו ("אם אין isHe — לגזור מ-locale", "אם RTL מתהפך — לפצל לצמתים") הם הוראות-מגירה עם פתרון מוגדר, לא שאלות פתוחות.

**סיכוני-רגרסיה על 24 המשתמשים:** הנקודה הרגישה היחידה באמת היא צעד 5 — הוא נוגע בנתיב-ההתחברות של **כולם**; ליקוי 1 הופך אותו מהוספה-בטוחה לבאג-בכניסה. תיקון ליקוי 2 בגרסת-הדשבורד מקטין את מגע-הטפסים לאפס. שאר השינויים (middleware בהתאמת-סגמנט-מדויקת, העברת-תיקייה, דיאלוג שעוטף handler קיים, כפתור-יומן מותנה כמו הקיימים) — סיכון נמוך, וה-Toaster אכן זמין גם בעמודים ציבוריים (`src/app/[locale]/layout.tsx:33`), כך שהעמוד המשותף לא יאבד toasts.

## מה חסר
(1) **צריכת-החזרה בדשבורד** במקום/בנוסף לטפסים — הפתרון האמיתי לליקויים 1-2. (2) **Cache-Control ל-OG** — הטוקן דטרמיניסטי; לוודא ש-ImageResponse אכן שולח cache immutable בפרוד (ברירת-מחדל של vercel/og) ולציין זאת, כי הראוט ציבורי, מחוץ ל-middleware, ובלי rate-limit — satori על כל בקשה הוא וקטור-עומס. (3) **זיוף-שם**: כל אחד יכול לייצר טוקן עם `n` שרירותי — "התוכנית של הדקאן" על הדומיין שלכם; חיתוך ל-30 תווים אינו הגנה. לפחות לציין את הסיכון בהחלטה 7, או לוותר על שם ב-OG. (4) **מדידה**: אין שום דרך לדעת אם הלולאה עובדת (אפילו ספירת-פתיחות של shared-plan בלוגים של Vercel) — הערה אחת במפרט הייתה מספיקה. (5) עדכון docs/משימות-בקרה.md כחלק מהגדרת-הסיום, לפי נוהל-הבית. חוץ מזה — עבודת-אימות של "מצב קיים" ברמה גבוהה מאוד: 90% מהציטוטים מדויקים עד השורה, וההיקש הטכני (btoa/Latin-1, TRPCReactProvider החסר ב-public, route-groups לא משנים URL) נכון.
