## ההחלטות (רשימה סגורה)

1. **נבנה מקור-אמת אחד:** מודול חדש `src/lib/academic-calendar.ts` עם תאריכי תשפ"ו+תשפ"ז המאומתים מהלוח הרשמי (המספרים שבסעיף ב' לעיל — לא אלה שבקוד היום). כל צרכן תאריכים/סמסטר עובר אליו. `SEMESTER_TEACHING_DATES` ו-`ACADEMIC_CALENDAR` נמחקים.
2. **הסמסטר נגזר מהתאריך, לא נשאל:** שיוך-סמסטר = FALL מתחילת-הוראה-א' ועד יום לפני תחילת-הוראה-ב'; SPRING משם ועד תחילת שנה"ל הבאה. שלב (`phase`): `teaching` / `exams` / `break`.
3. **שנת-הלימודים של הסטודנט נגזרת מעוגן:** `User.startYear` (קיים בסכמה, ריק) מאוכלס — באונבורדינג נגזר מהשנה שהסטודנט מצהיר, ולמשתמשים הקיימים במיגרציית-backfill. `currentYear/currentSemester` נשארים בסכמה כ-fallback בלבד.
4. **שאלת-הסמסטר בהגדרות נמחקת (#43):** במקומה Select יחיד "שנת תחילת התואר" + שורה נגזרת לקריאה-בלבד ("עכשיו: שנה ב' · סמסטר ב' תשפ"ו").
5. **"שיעורי היום" לא משקר (#39):** מחוץ ל-phase `teaching` מוצגת שורת-אמת שקטה (תקופת-בחינות / חופשה עם תאריך-חזרה) במקום שיעורים.
6. **המתכנן נפתח על עוגן-תכנון נגזר:** הסמסטר הנוכחי אם עוד מלמדים בו, אחרת הסמסטר הבא (`getPlanningAnchor`), עם שנת-הלימודים המתאימה לו.
7. **טאב-הגאנט ביומן נמחק** (weekly + exams נשארים). שלוש הערות-בעלים עוקבות + אפס תוכן ייחודי = הורדה, לא שיפוץ. עריכת-קורסים חיה במתכנן ("היחידה היא הלולאה"); המשימות חיות במתכנן-המבחנים.
8. **הכפילויות מתוקנות בשורש:** guard כפילות ב-`updateCourse` (CONFLICT ידידותי) + de-dupe לפי קוד-קורס ב-`getExamSchedule` (השורה האחרונה לפי מיון שנה/סמסטר מנצחת = הניסיון העדכני).
9. **בחירת-השעות מקבלת משמעות (#2):** (א) הבורר מוצג גם לקורסי-בחירה; (ב) שורת-הסבר אחת "בחירת הקבוצה קובעת מתי הקורס יושב במערכת"; (ג) צ'יפ נבחר בלבוש-אינדיגו הקנוני; (ד) hover על צ'יפ מציג preview מקווקו של הקבוצה על מערכת-השעות (dashed = "כאן יהיה משהו", לפי הקו-העיצובי). בלי drag&drop.
10. **מערכת-השעות עולה לראש העמודה (#20):** בעמודת-התוכן של המתכנן — קודם ה-LiveTimetable, מתחתיו "הסמסטר שלי". ממשיכים לשתף את `WeeklyTimetable` הקיים — לא בונים רכיב חדש.
11. **סמסטר-חובה-בלבד מקבל מסגור "אישור" ולא "בחירה":** כשאין קורסי-בחירה זמינים בפול — מצב-ריק מקווקו עם ההסבר "הסמסטר הזה כמעט כולו חובה — המערכת כבר מורכבת; נשאר רק לבחור קבוצות".

### שלב 1 — המודול `src/lib/academic-calendar.ts` (חדש) + בדיקות

```ts
// src/lib/academic-calendar.ts
// מקור-האמת היחיד לתאריכי שנה"ל של ת"א ולגזירת "איפה אנחנו עכשיו".
// תאריכים אומתו מול https://www.tau.ac.il/calendar (לוח מעודכן תשפ"ו + טאב תשפ"ז).

export type TeachingSemester = "FALL" | "SPRING";
export type AcademicPhase = "teaching" | "exams" | "break";

const d = (y: number, m: number, day: number) => new Date(y, m - 1, day); // חודש 1-based

interface SemesterDates {
  teachingStart: Date;
  teachingEnd: Date;      // היום האחרון ללימודים
  examStart: Date;
  examEnd: Date | null;   // null = לא פורסם; נספר עד תחילת הסמסטר הבא
}

export interface AcademicYearCalendar {
  startYear: number;      // 2025 = תשפ"ו
  labelHe: string;
  FALL: SemesterDates;
  SPRING: SemesterDates;
  summer?: { start: Date; end: Date };
}

export const TAU_CALENDARS: AcademicYearCalendar[] = [
  {
    startYear: 2025, labelHe: "תשפ״ו",
    FALL:   { teachingStart: d(2025,10,26), teachingEnd: d(2026,1,25), examStart: d(2026,1,28), examEnd: d(2026,3,13) },
    SPRING: { teachingStart: d(2026,4,12),  teachingEnd: d(2026,7,10), examStart: d(2026,7,12), examEnd: null },
    summer: { start: d(2026,7,26), end: d(2026,9,18) },
  },
  {
    startYear: 2026, labelHe: "תשפ״ז",
    FALL:   { teachingStart: d(2026,10,18), teachingEnd: d(2027,1,18), examStart: d(2027,1,20), examEnd: d(2027,3,8) },
    SPRING: { teachingStart: d(2027,3,9),   teachingEnd: d(2027,6,27), examStart: d(2027,6,29), examEnd: null },
    summer: { start: d(2027,7,20), end: d(2027,9,17) },
  },
];
```

פונקציות (כולן מקבלות `now: Date = new Date()` להזרקה בבדיקות):
- `getAcademicNow(now)` → `{ startYear, labelHe, semester, phase, dates, nextTeachingStart, isStale }`. כללי-שיוך: `FALL` אם `now ∈ [FALL.teachingStart, SPRING.teachingStart)`; `SPRING` אם `now ∈ [SPRING.teachingStart, nextCal.FALL.teachingStart)`; לפני הלוח הראשון — משייכים ללוח הראשון עם `isStale=true`; אחרי האחרון — נשארים על SPRING האחרון עם `isStale=true`. `phase`: `teaching` עד `teachingEnd` (כולל); `exams` מהיום שאחרי `teachingEnd` ועד `examEnd` (ואם `examEnd===null` — עד סוף חלון-השיוך); `break` אחרי `examEnd` ועד הסמסטר הבא.
- `getPlanningAnchor(now)` → `{ startYear, semester }` — הסמסטר הנוכחי אם `phase==="teaching"`, אחרת סמסטר-ההוראה הבא (SPRING של אותה שנה או FALL של הבאה).
- `deriveYearOfStudy(startYear: number | null, storedYear: number, atStartYear?: number, now?)` → אם `startYear==null` מחזיר `storedYear`; אחרת `clamp((atStartYear ?? getAcademicNow(now).startYear) - startYear + 1, 1, 4)`.
- `hebrewYearLabel(startYear)` → מפה `{2023:"תשפ״ד",2024:"תשפ״ה",2025:"תשפ״ו",2026:"תשפ״ז",2027:"תשפ״ח"}`, fallback `` `${y}/${(y+1)%100}` ``.
- `getTeachingRange(semester, now)` — לייצוא ICS/גוגל: אם הסמסטר המבוקש הוא הנוכחי ו-`now <= teachingEnd` — הטווח הנוכחי; אחרת המופע הבא שלו בלוחות.

בדיקות: `src/lib/__tests__/academic-calendar.test.ts` — מקרים חובה: 25.10.25 (stale/לפני), 26.10.25 (FALL/teaching), 26.1.26 (FALL/exams — יום היערכות), 13.3.26 (FALL/exams), 14.3.26 (FALL/break), 12.4.26 (SPRING/teaching), **7.7.26 (SPRING/teaching — התיקון המהותי)**, 12.7.26 (SPRING/exams), 17.10.26 (עדיין SPRING תשפ"ו), 18.10.26 (FALL תשפ"ז), 1.7.27 (SPRING תשפ"ז/exams), 1.12.27 (isStale). ל-`deriveYearOfStudy`: startYear=2024 ב-7.7.26 → 2; ב-18.10.26 → 3; null → storedYear; clamp ל-4. ל-`getPlanningAnchor`: 7.7.26 → SPRING-2025 (עדיין teaching); 13.7.26 → FALL-2026; 1.2.27 → SPRING-2026.

## סיכונים ונקודות-שבירה
1. **תיקון-התאריכים משנה התנהגות חיה:** משתמשים שסנכרנו לגוגל עם הטווח הישן יקבלו בסנכרון-חוזר אירועים מעודכנים (upsert לפי googleEventId — schedule.ts:427-447 — מונע כפילויות), אבל אירועים ישנים שכבר "הסתיימו" ב-12.6 לא יתארכו בלי סנכרון-חוזר. לקבל כעובדה; לא לבנות מנגנון-תיקון.
2. **סוף-בחינות ב' לא פורסם:** מודלנו exams-עד-הסמסטר-הבא. משפיע רק על תווית-phase בקיץ; אם ת"א תפרסם — לעדכן `examEnd` במקום אחד.
3. **קידום-שנה אוטומטי ב-18.10.26:** סטודנט שהקפיא שנה יוצג שנה מתקדם מדי — Select שנת-ההתחלה בהגדרות הוא מנגנון-התיקון; לוודא שהוא באמת כותב `startYear`.
4. **ה-backfill מניח הרצה בתשפ"ו:** ה-SQL עם הקבוע 2025 נכון רק עד 17.10.26. אם הביצוע נדחה מעבר לזה — לעדכן את הקבוע במיגרציה.
5. **סדר מיגרציה→קוד:** אם הקוד הנגזר נפרס לפני ה-backfill — ה-fallback (`storedYear`) מכסה, אבל שורת-ההגדרות תציג שנה נגזרת רק אחרי שמירת-הגדרות ראשונה. לפרוס מיגרציה קודם.
6. **מחיקת הגאנט מוחקת גם את "העבר לסמסטר" מהיומן:** הפעולה נשארת זמינה דרך המתכנן; אם אריאל ירגיש בחסר — זו החלטת-טעם הפיכה (הקומפוננטה בהיסטוריית-גיט), לא לבנות תחליף עכשיו.
7. **CONFLICT חדש ב-updateCourse:** צרכן שלא הוסיף onError ידידותי יציג toast גנרי. לוודא ב-grep שכל `updateCourse.useMutation` עם שינוי-סמסטר קיבל טיפול (אחרי מחיקת הגאנט נשאר בעיקר academic-record-content).
8. **hydration:** הפונקציות תלויות-שעון; לקרוא להן רק ברכיבי-client (כמו היום ב-TodaysClasses) — לא ב-RSC — כדי לא לפתוח פער server/client סביב חצות.
