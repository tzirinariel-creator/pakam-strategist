### שינוי 2 — ביטול N+1 של `user.findUnique` בפרוצדורות ההוט

ה-`ctx.user` כבר קיים בכל `protectedProcedure` (מוזרק ב-`init.ts:110`). כל פרוצדורה שמריצה `user.findUnique({ where: { supabaseId: ctx.userId } })` בתחילתה — מחליפה בקריאה ל-`ctx.user`.

**קובץ `src/server/routers/plan.ts`** — ב-3 הפרוצדורות ההוט (getUserPlan:18, getCredits:255, getGraduationScore:294):

```ts
// לפני:
const user = await ctx.db.user.findUnique({
  where: { supabaseId: ctx.userId },
});
if (!user) {
  throw new TRPCError({ code: "NOT_FOUND", message: "User not found" });
}

// אחרי:
const user = ctx.user;   // כבר נטען ואומת ב-enforceAuth (init.ts:74,110)
```

זהה ב:
- `src/server/routers/regulation.ts:14` (checkCompliance)
- `src/server/routers/user.ts:17` (getProfile)
- `src/server/routers/schedule.ts:225` (getGoogleStatus)

**הערת-טיפוס**: `ctx.user` מוזרק דרך `next({ ctx: { ...ctx, user } })`, אז הטיפוס אמור להיות זמין ל-`protectedProcedure`. אם TypeScript מתלונן שאין `user` על ה-ctx (בגלל שה-cast ב-`init.ts:130` נעשה ידנית ב-adminProcedure), הפתרון הנקי: ודא ש-`next({ ctx: { ...ctx, user }})` ב-`enforceAuth` (init.ts:109-115) מרחיב את טיפוס ה-ctx — הוא כן, כי tRPC מסיק את ה-ctx החדש מה-`next`. אם בכל זאת יש בעיה, השאר את `const user = ctx.user!` עם הערה. **אין** להחזיר את ה-findUnique.

**זהירות — לא לגעת ב-`ctx.userId`**: פרוצדורות שכן צריכות את `user.id` (ה-PK הפנימי) ל-`where: { userId: user.id }` — ימשיכו לעבוד כי `ctx.user.id` זהה ל-`user.id` שהוחזר מ-findUnique. רק מחליפים את מקור השורה.
