# 2) לאריאל — סיכום פשוט

## א. המערכת החברתית — מה אני ממליץ ולמה
ממליץ על מודל **אנונימי לגמרי ומצרפי**: סטודנטים תורמים על קורסים (עומס, קושי, המלצה, טיפ קצר) וגם את הציון שלהם — אבל אף ציון בודד לא נחשף לעולם, רק ממוצע/חציון, ורק אחרי שיש לפחות 5 תורמים לקורס (דירוגים — 3). את הציונים שומרים בטבלה **בלי שם בכלל**, כך שאפילו דליפה לא תחשוף מי קיבל כמה. הסיבה שזה הנכון: בקהילה של 24 אנשים, לחשוף "פלוני קיבל 71" זו פגיעה ודאית — אז ההפרדה הזו היא ההגנה. ואת בעיית ה"אין נתונים בהתחלה" פותרים בלחיצה אחת: כבר יש להם ציונים שהזינו בגיליון — כפתור "תרמו באנונימיות" הופך את זה ל-~360 נקודות ביום הראשון. תמיד אפשר גם למשוך הכל בחזרה.

## ב. השם — 3 לבחירה
1. **תכלית** (ההמלצה שלי) — גם "טלוס" הפילוסופי (המלך הפילוסוף) וגם "תכל'ס, בוא נגיע לעניין" — בדיוק איך שהמלך מדבר. עברי, קצר, חם, לא תקוע בראשי-תיבות.
2. **אקדם** — מ"אקדמוס", החורשה של אפלטון ומקור המילה "אקדמיה". רציני ויוקרתי, הפילוסופיה בשקט.
3. **מצפן** — פשוט וברור, אבל גנרי ויש כבר אפליקציות בשם הזה.

**השורה התחתונה:** אל תחליף שם עכשיו סתם — "פכמון" עובד בקהילה ולא עולה כלום. תכנן מעבר ל**תכלית** בהשקה הבאה. את הכתר של המלך להשאיר כסמל, לא כשם.

## ג. כיוון העיצוב שאני ממליץ
**לחדד ולאכוף את השפה הקיימת (אינדיגו/זהב/מלך) — לא לעצב מחדש.** הקו-העיצובי שלך מצוין ועדכני; מה שמרגיש "מיושן" זה שהקוד לא מציית לחוקים של עצמו, ושחסרות שכבות-יסוד במובייל. הכי דחוף: **תשתית מובייל** — היום כפתורים ותוכן נחבאים מאחורי סרגל-הבית של האייפון, ויש padding כפול שיוצר את תחושת-הצפיפות שדיווחת עליה. אחרי זה: קצב אחיד, כותרת אחת קנונית בכל עמוד, וספינרים אחידים. המסכים הכי דחופים לתיקון: התיק, הבית, המתכנן.

## ד. גישת האינטראקטיביות (מתכנן + מבחנים)
- **מתכנן:** מעבירים את בחירת קבוצות-התרגול **לתוך מערכת-השעות עצמה** — לוחצים על בלוק, נפתח חלון קטן, וכל אפשרות שמתנגשת מסומנת מראש באדום. הכל בלחיצה, בלי גרירה, עובד חלק בטלפון. וגם: "רמת העומס" תוחלף ב-3 מספרים אמיתיים (שעות שבועיות, ש"ס, הפער הקטן ביותר בין מבחנים), והתווית תיקבע לפי הגרוע מביניהם.
- **מבחנים:** המנוע כבר טוב, אז משדרגים — **אשף של 4 שאלות** לפני בניית התוכנית (אילו מבחנים, איך אתם מתכוננים, אילו ימים חסומים, ותצוגה-מקדימה), **ייצוא Excel צבעוני אמיתי**, ו**איחוד הגרפים** (הגרף החלש ביומן יוחלף ב-Skyline הטוב). מוֹעד א'/ב' נשאר בטוח: האפליקציה **לא מנחשת תאריכים ולא מנבאת קושי** — רק מסבירה בגלוי.
- **עיקרון-על משותף:** בשום מקום לא מנבאים ניקוד, לא מנחשים תאריכים שלא פורסמו, ולא מעודדים "לתפוס קורס קל" — רק מראים מה היה, ביושר.

## 1. מודל הפרטיות — ההחלטה

**המלצה: אנונימי מלא + אגרגט, עם סינון-מחזור אופציונלי מעל סף. שני סוגי תרומה נפרדים לחלוטין:**

| סוג | מה נאסף | פרטיות |
|---|---|---|
| **A. נקודת-ציון** (מיובאת אוטומטית) | הציון המספרי של המשתמש בקורס שהשלים | **מנותקת לגמרי מזהות**. נשמרת בטבלה נפרדת בלי `userId`. מוצגת רק כאגרגט (ממוצע/חציון/פיזור) מעל סף. |
| **B. דירוג+ביקורת** (הזנה מפורשת) | עומס (1–5), קושי (1–5), מומלץ? (כן/לא), טקסט חופשי קצר, תגיות | אנונימי ל**צופה**, אך מקושר ל-`userId` **בבסיס בלבד** (לצורך "תרומה אחת למשתמש לקורס" + מחיקה/מודרציה). לעולם לא נחשף מי כתב. |

### למה זה הפתרון הנכון (ולא האחרים)
- **לא "מזוהה"**: ציונים הם מידע רגיש-קיצוני. חשיפת "פלוני קיבל 71 בפילוסופיה" בקהילה של 24 אנשים = פגיעה ודאית. מזוהה נפסל.
- **לא "אנונימי-לגמרי-בלי-שום-קישור"**: אם אין שום קישור בבסיס לדירוגים, אי-אפשר לאכוף "תרומה אחת לאדם" (הצבעה כפולה מטה את הממוצע) ואי-אפשר למחוק ביקורת פוגענית של משתמש ספציפי. לכן דירוגים **כן** מקושרים ל-userId בבסיס — אבל ה-API שקורא לעולם לא מחזיר את הקישור.
- **הפרדת נקודת-ציון מזהות פיזית**: הציון הוא הנתון הכי רגיש, אז הוא לא נשמר עם userId **בכלל**. גם דליפת-בסיס לא תחשוף מי קיבל כמה. הפרדה זו היא ההגנה החזקה ביותר.

### סף החשיפה (k-anonymity)
- **אגרגט ציונים** מוסתר עד **N ≥ 5** נקודות-ציון ייחודיות. פחות מזה → מציגים "עדיין אין מספיק נתונים (צריך 5, יש X)".
- **דירוגי עומס/קושי** מוסתרים עד **N ≥ 3** דירוגים.
- **ביקורות טקסט** מוצגות מיד (טקסט אחד לא חושף ציון), אך ממותנות (ראו §5).
- **סינון-מחזור**: ניתן לסנן אגרגט לפי `startYear` **רק אם באותו מחזור יש N≥5 בנפרד**. אחרת הסינון מושבת עם הסבר. זה מונע דה-אנונימיזציה ("המחזור של 2024, קורס נדיר → 2 אנשים").

## 2. מודל הנתונים (Prisma) — `prisma/schema.prisma`

שני מודלים חדשים. שניהם מפתחים לפי `courseCode` (String), עקבי עם `StudyMaterial`/`Syllabus`/`ScheduleSession` שכבר עושים כך.

```prisma
enum RecommendVerdict {
  RECOMMEND       // כן, שווה
  NEUTRAL         // ניטרלי
  AVOID           // הייתי מדלג
}

enum ReviewStatus {
  VISIBLE
  HIDDEN          // הוסתר ע"י מודרציה / דיווחים
  PENDING         // ממתין (אם מפעילים תור; ב-MVP לא בשימוש)
}

// ---- A. נקודת-ציון אנונימית. אין userId בכוונה. ----
// נגזרת מ-UserCourse שהושלם, אך מנותקת פיזית מהזהות.
model CourseGradePoint {
  id          String   @id @default(uuid())
  courseCode  String
  grade       Float                    // 0–100, לא-binary בלבד
  cohortYear  Int?                     // = User.startYear ברגע התרומה (לסינון-מחזור); nullable
  isBinary    Boolean  @default(false) // binary נספר לנפח אך לא נכנס לממוצע
  source      String   @default("import") // "import" | "manual"
  createdAt   DateTime @default(now())

  @@index([courseCode])
  @@index([courseCode, cohortYear])
  @@map("course_grade_points")
}

// ---- B. דירוג + ביקורת. מקושר ל-userId בבסיס בלבד (לאכיפת ייחוד+מודרציה). ----
// ה-API שקורא לעולם לא מחזיר userId.
model CourseReview {
  id            String            @id @default(uuid())
  userId        String            // בבסיס בלבד — לעולם לא נחשף לצופה
  courseCode    String
  cohortYear    Int?              // = User.startYear ברגע התרומה
  workload      Int?              // 1–5 (שעות/עומס שבועי), אופציונלי
  difficulty    Int?              // 1–5 (קושי חומר), אופציונלי
  verdict       RecommendVerdict?
  tip           String?           // טקסט חופשי, ≤ 400 תווים; טיפ אחד ענייני
  tags          String[]          // תגיות סגורות מרשימה מבוקרת (ראו §4)
  status        ReviewStatus      @default(VISIBLE)
  reportCount   Int               @default(0)

  user          User              @relation(fields: [userId], references: [id], onDelete: Cascade)

  createdAt     DateTime          @default(now())
  updatedAt     DateTime          @updatedAt

  @@unique([userId, courseCode])   // תרומה אחת לאדם לקורס (ניתנת לעדכון)
  @@index([courseCode])
  @@index([courseCode, status])
  @@map("course_reviews")
}
```

הוסף ל-`User`: `courseReviews CourseReview[]`.

**מיגרציה**: `prisma migrate dev --name add_cross_cohort_knowledge`. תואם לתבנית הקיימת ב-`prisma/migrations/`. אין שינוי בטבלאות קיימות → additive לחלוטין.

### שאלת מפתח: איך נמנעת הצבעה כפולה על נקודת-ציון בלי userId?
נקודת-ציון **נגזרת מ-`UserCourse` הייחודי** (`@@unique([userId, courseId, attemptNumber])`). בזמן היבוא כותבים שדה-חתימה דטרמיניסטי כדי לזהות "כבר תרמתי את הקורס הזה" **בלי לשמור מי**:

הוסף ל-`CourseGradePoint`:
```prisma
  dedupeHash  String   @unique   // sha256(userId + ":" + courseCode) — חד-כיווני
```
כך: אם המשתמש מייבא שוב, ה-hash מתנגש → upsert (מעדכן grade אם השתנה), לא כפילות. ה-hash חד-כיווני ולא הפיך לזהות, אבל מבטיח נקודה אחת לאדם לקורס. `crypto.ts` כבר קיים בפרויקט לשימוש.

## 3. tRPC — ראוטר חדש `src/server/routers/course-knowledge.ts`

רשום ב-`src/server/trpc/router.ts` כ-`courseKnowledge`.

```ts
// קבועים
const GRADE_MIN_N = 5;
const RATING_MIN_N = 3;
```

### 3.1 `getForCourse` — קריאה ציבורית (publicProcedure)
קלט: `{ courseCode: string, cohortYear?: number }`. מחזיר את **האגרגט בלבד**, אף פעם לא שורות גולמיות:

```ts
{
  grade: {
    n: number,                 // כמה נקודות-ציון (כולל binary לצורך "כמה לקחו")
    nGraded: number,           // כמה עם ציון מספרי (לא-binary)
    revealed: boolean,         // nGraded >= GRADE_MIN_N
    average: number | null,    // מעוגל ל-0.1, רק אם revealed
    median: number | null,
    p25: number | null, p75: number | null,  // טווח, לא ציונים בודדים
    binaryShare: number | null // אחוז שלקחו binary — אות "קורס ידוע כקשה"
  },
  ratings: {
    n: number,
    revealed: boolean,         // n >= RATING_MIN_N
    workloadAvg: number | null,
    difficultyAvg: number | null,
    recommendShare: number | null // % שסימנו RECOMMEND
  },
  reviews: Array<{             // רק status=VISIBLE, ללא userId, ללא cohortYear אם N נמוך
    id: string,
    tip: string,
    tags: string[],
    verdict: RecommendVerdict | null,
    createdAt: Date,
    cohortLabel: string | null // "מחזור 2023" רק אם באותו מחזור N≥5 ביקורות; אחרת null
  }>,
  cohortsAvailable: number[]   // רשימת מחזורים שיש להם N≥GRADE_MIN_N (למסנן)
}
```

הערה קריטית לחישוב: `average`/`median` נגזרים **רק** מנקודות `isBinary=false`. `binaryShare = binaryCount / n`. אם מסננים לפי `cohortYear` — בודקים סף בנפרד לאותו מחזור; אם לא עובר, מתעלמים מהמסנן ומחזירים `revealed:false` עם דגל `cohortSuppressed:true`.

### 3.2 `contributeReview` — protectedProcedure (mutation → נחסם אוטומטית לדמו)
קלט (Zod, מקביל ל-`grade-sheet.ts`):
```ts
{
  courseCode: z.string().min(1).max(30),
  workload: z.number().int().min(1).max(5).optional(),
  difficulty: z.number().int().min(1).max(5).optional(),
  verdict: z.enum(["RECOMMEND","NEUTRAL","AVOID"]).optional(),
  tip: z.string().trim().max(400).optional(),
  tags: z.array(z.enum(ALLOWED_TAGS)).max(6).default([]),
}
```
לוגיקה: מוודא שהקורס קיים (`course.findUnique by code`). קורא `startYear` מ-`ctx.user`. `upsert` על `@@unique([userId, courseCode])`. חובה **לפחות אחד** מ-{workload, difficulty, verdict, tip} — אחרת `BAD_REQUEST`. אם tip לא ריק → מריץ `moderateTip` (§5) לפני שמירה.

### 3.3 `importMyGrades` — protectedProcedure (הליבה של cold-start)
בלי קלט. סורק את כל `UserCourse` של המשתמש עם `status=COMPLETED`, מייצר/מעדכן `CourseGradePoint` לכל אחד עם `dedupeHash = sha256(user.id + ":" + courseCode)`:
- `grade` = `uc.grade` (אם `isBinary` → grade=null בפועל, נשמר `isBinary:true`, לא נכנס לממוצע)
- `cohortYear` = `user.startYear`
- `source = "import"`
- upsert לפי `dedupeHash` → אידמפוטנטי (ריצה חוזרת לא מכפילה)

מחזיר `{ imported: number }`. **זו פעולה מפורשת בהסכמה** (לחצן "תרמו את הציונים שלכם באנונימיות") — לא רצה אוטומטית. ראו §6 אתיקה.

### 3.4 `withdrawMyContributions` — protectedProcedure
זכות-נסיגה (חשוב לפרטיות ולתקנון): מוחק את כל `CourseReview` של המשתמש + כל `CourseGradePoint` עם `dedupeHash` שתואם לו. נותן שליטה מלאה בחזרה.

### 3.5 `reportReview` — protectedProcedure
קלט `{ reviewId }`. מגדיל `reportCount`. כש-`reportCount ≥ 3` → `status=HIDDEN` אוטומטית (ראו §5). מונע דיווח כפול דרך שדה נלווה או פשוט מקבל (MVP: לא עוקב מי דיווח, סף 3 מספיק).

## 4. משטח ה-UI — איפה זה חי

**החלטה: לב המערכת חי ב-`course-detail-modal.tsx`**, מתחת לגוש-הציון ההיסטורי הקיים. זה המקום היחיד שכבר "מבט הקורס האמיתי", וכבר מכיל את דיסקליימר-הכנות. לא טאב חדש (מפצל תשומת-לב), לא עמוד חדש.

### 4.1 בתוך `course-detail-modal.tsx` — שלושה בלוקים חדשים אחרי גוש-הציון:

**בלוק 1 — "מה הסטודנטים אומרים" (אגרגט קהילתי):**
- שורת מטריקות: עומס ●●●○○, קושי ●●●●○, "% ממליצים 78%". מוצג רק אם `ratings.revealed`.
- אם `!revealed`: משפט עמום "עדיין אין מספיק דירוגים לקורס הזה — היו הראשונים." + כפתור "דרגו את הקורס".
- **הבחנה כנה מ-Arazim**: כותרת-משנה "מהסטודנטים באפליקציה (N=12)" מול הבלוק הקיים "מנתוני עבר (Arazim)". שני מקורות, מסומנים במפורש — עקבי עם עקרון שני-המשפטים בעמוד הקטלוג.

**בלוק 2 — ציון קהילתי (אם `grade.revealed`):**
- "ממוצע קהילתי X.X · חציון Y · טווח 25–75: A–B (N=8)". אם `binaryShare` גבוה: שורת-אות "K% לקחו כ-binary". אם `!revealed`: "צריך 5 תורמים, יש 3."
- מסמן: "מהתורמים באפליקציה, לא ציון רשמי" (אותה כנות).

**בלוק 3 — טיפים (ביקורות טקסט):**
- רשימת עד 5, כרטיסים קטנים: תג-verdict (המלצה/ניטרלי/הייתי מדלג), tags, טקסט, `cohortLabel` אם קיים. כפתור "דווח" זעיר לכל טיפ.
- כפתור תחתון: "הוסיפו טיפ / דרגו את הקורס" → פותח `ContributeReviewSheet`.

### 4.2 קומפוננטה חדשה `src/components/catalog/contribute-review-sheet.tsx`
Radix Dialog (פורטל, כמו הקיים). טופס: שני סליידרים 1–5 (עומס/קושי), שלושה כפתורי-verdict, שדה טקסט (≤400, מונה תווים), צ'יפים לבחירת tags. `api.courseKnowledge.contributeReview`. במצב הצלחה: toast "תודה — עזרתם למחזור הבא." הטופס singular? לא — קול-מוצר רבים ("דרגו", "שתפו").

**`ALLOWED_TAGS`** (רשימה סגורה, ב-`src/lib/course-knowledge-tags.ts`):
`["מרצה_מעולה","בוחן_קשה","עבודה_גדולה","נוכחות_חובה","ציון_נדיב","הרבה_קריאה","מומלץ_למיקוד","טוב_לתואר_ראשון","עומס_בסוף"]` (label עברי/אנגלי לכל אחת). תגיות סגורות = אין שדה-טקסט-חופשי לזליגה, קל לסינון, אין abuse-surface פתוח.

### 4.3 חיבור לזרימת בחירת-הבחירה במתכנן
ב-`course-table.tsx` הוסף עמודה/צ'יפ זעיר "עומס קהילתי" (מוצג רק כשיש נתון), ליד עמודת הציון הקיימת. **חיבור עדין**: לא query נפרד לכל שורה — הוסף ל-`course.list` הקיים `select` מצומצם של אגרגט-דירוג מחושב-מראש (ראו §7 ביצועים). ב-`add-course-modal.tsx` (בחירת קורס במתכנן) הצג את אותו צ'יפ עומס/המלצה — שם ההחלטה קורית.

### 4.4 מצבי-קצה / cold-start / מובייל
- **empty state ראשוני** (0 תורמים בקורס): לא מציגים מספרים ריקים; מציגים הזמנה יחידה: "עדיין אין מידע קהילתי לקורס הזה. תרמתם קורס שהשלמתם? עזרו למחזור הבא." + CTA ליבוא.
- **באנר-הצטרפות חד-פעמי** בעמוד `record` (איפה שהציונים כבר יושבים): "יש לכם X קורסים שהשלמתם. תרמו אותם באנונימיות כדי לבנות ידע משותף." לחצן → `importMyGrades`. זו נקודת ה-cold-start החזקה: 24 משתמשים × ~15 קורסים שהושלמו = ~360 נקודות-ציון ביום ההשקה, בלי לחכות לתרומות חדשות.
- **מובייל**: הבלוקים נערמים אנכית בתוך ה-Dialog הקיים (כבר `max-h-[85vh] overflow-y-auto`). סליידרים → כפתורי-מדרגה נגישים למגע. רצפת גופן ≥12px.

## 5. מודרציה ומניעת-abuse

- **טקסט**: `moderateTip` ב-`src/lib/course-knowledge-moderation.ts` — פונקציה טהורה שרצה בצד-שרת לפני שמירה: (1) חוסמת קישורים/מיילים/טלפונים (regex), (2) רשימת-מילים-אסורות עברית+אנגלית, (3) חוסמת שמות פרטיים של מרצים בהקשר-השמצה — MVP: פשוט חוסמת ביטויי-גנאי ומחזירה `BAD_REQUEST` עם הודעה ידידותית. לא AI ב-MVP (עלות+latency); אפשר לשדרג ל-Gemini-moderation בגל-2.
- **תרומה אחת לאדם לקורס** (`@@unique`) → מונע הצפה/מניפולציה של ממוצע.
- **סף-דיווח**: `reportCount ≥ 3` → הסתרה אוטומטית (`status=HIDDEN`), ואז ריוויו אדמין.
- **פאנל אדמין**: הרחב `src/server/routers/admin.ts` + עמוד admin קיים ב-`listReported` / `setReviewStatus` (VISIBLE/HIDDEN). `adminProcedure` כבר קיים.
- **קצב**: `rate-limit.ts` כבר קיים — עטוף את `contributeReview`/`reportReview` (למשל 20 תרומות ליום).

## 6. אתיקה ובטיחות — התאמה לעקרון-הכנות של פכמון

זה הסעיף שאסור לפספס — פכמון בנוי על "מספרים כנים, אפס חיזוי-ניקוד".

1. **אין חיזוי-ניקוד/גיימינג**: המערכת מציגה עבר מצרפי (מה היה), לא ניבוי (מה יהיה) ולא "איך לתפוס נקודות במכרז". תואם למזכר [Bidding: never predict points]. שום המלצה לא אומרת "קח את X כי קל לצבור נקודות".
2. **הפרדת מקורות מפורשת**: אף פעם לא ממזגים את הציון-הקהילתי עם ה-Arazim למספר אחד. שני מקורות מסומנים = הצופה יודע מה הוא רואה. תואם עקרון-שני-המשפטים בקטלוג.
3. **סף-חשיפה מחייב** (N≥5 ציון, N≥3 דירוג, סינון-מחזור רק מעל סף) = אף יחיד לא נחשף. הפרדת נקודת-ציון מ-userId פיזית = גם דליפת-בסיס לא חושפת אישית.
4. **הסכמה + נסיגה**: יבוא הוא opt-in מפורש; `withdrawMyContributions` מוחק הכל. חובה עדכון `privacy/page.tsx` + `terms/page.tsx` (הקבצים קיימים): מה נאסף, שהוא אנונימי-מצרפי, ושאפשר למשוך.
5. **בלי "ציון נדיב = קח את זה"**: `verdict` הוא "שווה/ניטרלי/הייתי מדלג" מבחינת **ערך-לימודי**, לא "קל לציון". התגית `ציון_נדיב` היא עובדה מדווחת, לא המלצה. הקופי לא מעודד לבחור קורס רק בגלל ציון.

- אגרגט לא מחושב לכל render. הוסף **materialized aggregate** מרוענן ב-cron קיים (`src/app/api/cron/`): מודל קטן `CourseKnowledgeAgg` (courseCode PK, ratingN, workloadAvg, difficultyAvg, recommendShare, gradeN, gradeAvg, gradeMedian, updatedAt) שמתעדכן כל 6ש או ב-`contributeReview`/`importMyGrades` (עדכון-דלתא). `course.list` עושה `join`/lookup זול לצ'יפ-הטבלה. `getForCourse` קורא agg + טוען עד 5 ביקורות טקסט חיות. עם 24 משתמשים אפשר גם לחשב חי ב-MVP; ה-agg הוא אופטימיזציה לגל-2.

# מחקר שמות ל"פכמון" — Naming Research & Shortlist

## 1. What the name has to carry (grounded in the code)

From the actual app (`src/messages/he.json`, `manifest.ts`, `about/page.tsx`):

- **The mission** — the app's own words: *"פכמון נולד מתסכול אמיתי: הידיעון הוא טבלת ASP.NET משנות ה-2000, התקנון הוא PDF של 40 עמודים, ואין שום כלי שמחבר בין השניים."* The product turns **chaos → one clear plan**. The current tagline is already the perfect brief: **"התואר שלכם, מסודר סוף סוף."**
- **The persona** — `המלך הפילוסוף` (Philosopher King, gold crown) is the AI advisor's face; `רפרנט` (a final-year peer) is the second voice. Plato's *Republic* is baked into the identity.
- **The scope** — 3 disciplines, 150 ש״ס, TAU PPE only (today). The name should not paint the app into "TAU-only" forever (the about page already says *"בעתיד אני מתכנן להרחיב"*).
- **The reality on the ground** — `pakamon.app` domain is owned; `ariel@pakamon.app` is the contact; ~24 users, friends-of-friends, already say "פכמון". The name has **existing equity**. Throwing it away has a real cost.

**Strategic read:** "פכמון" is a *descriptive-diminutive* — "פכ״מ" + the affectionate "-ון" suffix (like פינגווין→פינגוונון, a little friendly thing). Its strength is instant in-group recognition: any פכ״מ student decodes it in 0.5s. Its weakness is that it's **inside-baseball** (means nothing to anyone outside the program), slightly childish in tone for a tool that also computes your final GPA and checks regulations, and it locks the brand to one 3-letter acronym at one university.

So the real decision is a fork:

> **A) Keep-and-own "פכמון"** (it already works, has equity, costs nothing) — polish its story, or
> **B) Graduate to a name that carries the mission + the Philosopher-King identity** and can travel beyond TAU.

I'll give you a genuine shortlist for (B), then a clear recommendation across the fork.

## 3. Recommendation

### First, the fork verdict — **keep "פכמון", but only as the interim.**

For today, at 24 users with the domain owned and word-of-mouth running on the exact string "פכמון", a rename has real switching cost and near-zero upside. The name *works* inside the tribe. **Do not rename reactively.** If you touch nothing, you lose nothing.

But you asked whether it's "good enough," and honestly: **for the product it's becoming, no.** "פכמון" is a nickname, not a brand. It's affectionate but slightly juvenile for a tool that computes your final GPA, checks a 40-page regulation, and speaks in the voice of a Philosopher King. It can't leave TAU. So plan the graduation now, and pull the trigger at the natural moment — when you expand past פכ״מ, or do a real launch.

### 🥇 TOP recommendation: **תכלית (Tachlit)**

**Why it wins the whole brief:** it's the only candidate that fuses *both* halves of the app's soul. On the philosophical side, **תכלית = telos**, the purpose/end-goal — exactly the register of the Philosopher King and the *Republic* DNA. On the practical side, "תכל'ס / בוא נדבר תכלית" is the most Israeli way to say *"cut the intro, get to the point"* — which is **verbatim** how the code describes the advisor: *"עונה קודם, בלי הקדמות."* One word says: *this tool has a philosophy, and it wastes none of your time.* It's warm, unmistakably Hebrew (no foreign-transliteration friction, RTL-clean, no `<Bidi>` needed), short, and memorable. It reframes the product from "a cute helper for פכ״מ" to "the thing that gets you to your degree's purpose." And it travels — nothing in it is bound to one acronym.

Pairing: **תכלית** as the brand, with the descriptor line **"התואר שלכם, מסודר סוף סוף"** you already ship. Domain: `tachlit.app` / try `tachlit.co.il`.

### 🥈 Runner-up: **אקדם (Akadem)**

If you want the philosophy to be a *quiet* signal rather than a Hebrew pun, **אקדם** is the sophisticated pick. It descends from *Akademos* — Plato's grove, the literal origin of "academy" — so the Philosopher-King persona has a real etymological home, while any Israeli hears "academic." It's short, premium, and brandable (`akadem.app`). It loses to תכלית only because it's a touch cooler/more institutional and less distinctive as a Hebrew string — but it's the safer, more "serious product" choice if that's the direction you want.

**One to avoid despite the pull:** *כתר/Keter*. The crown is a gorgeous *icon*, but as a *name* it collides with a giant Israeli brand and Kabbalah — keep the crown as the King's mark, not the app's name.

```ts

  // 1. שעות-מגע/שבוע — סכום weeklyHours (fallback: סכום משכי-הסשנים הנבחרים מהרשת)
```

**כלל התווית (כנה — הגרוע קובע):**

## 4. סמסטר-חובה-כבד מול סמסטר-בחירה-כבד (הדגשות-UI שונות)

הבחנה קיימת חלקית (`course-pool.tsx:263` — מצב "כמעט-הכל-חובה"). להפוך אותה לעקרון-פריסה מפורש. חישוב: `mandatoryRatio = mandatoryCredits / semesterCredits`.

**מצב A — חובה-כבד (`mandatoryRatio ≥ 0.75`)** — טיפוסי לשנה א׳:
- הכותרת-על של המסך: "הסמסטר שלכם כבר מורכב — נשאר לבחור קבוצות ולאשר."
- מערכת-השעות **מוקדמת ומורחבת** (התפקיד המרכזי); `CoursePool` **מתקפל** לכרטיס-נפתח צר ("הוסיפו קורס בחירה +") כי כמעט אין מה לבחור.
- ה-CTA התחתון: "אשרו את המערכת" (לא "סיימתי").
- הדגש-פעולה: הבלוקים הלא-מאושרים בורר-הקבוצה (סעיף 2.3).

**מצב B — בחירה-כבד (`mandatoryRatio < 0.75`)** — טיפוסי לשנים ב׳–ג׳:
- `CoursePool` **פתוח ובולט** משמאל; מערכת-השעות מימין כ"תצוגה-חיה" של מה שנאסף.
- הדגש-פעולה: מספר-ש"ס-שנותר-להשלמה + התאמה-לתחום-מיקוד (כבר קיים באינסייטס).
- אזהרות-חפיפה בולטות יותר (בבחירה, חפיפה = טעות; בחובה, לרוב אין ברירה).

מימוש: prop `emphasis: "mandatory" | "elective"` שנגזר ב-`index.tsx` ומועבר ל-`CoursePool` (מתקפל/פתוח), ל-container-ה-layout (סדר-עמודות), ול-CTA. ברירת-מחדל אם 0-קורסים: `elective`.

## 2. רכיב חדש #1 — אשף רצף-השאלות `ExamPlanWizard` (#37, #34, #15)

**קובץ חדש:** `src/components/exam-planner/exam-plan-wizard.tsx`

**מטרה:** במקום שהסטודנט רק יסמן צ'קבוקסים, שאלון-קצר (4 צעדים) שמכוונן את התוכנית. הפלט מוזרם ל-`generateExamPlan` דרך פרמטרים חדשים.

**מתי מוצג:** ב-STATE A בלבד, כשלב ראשון *לפני* ה-`pickExamsPanel` הקיים — או ליתר דיוק, **האשף הופך למעטפת של `pickExamsPanel`**. צעד 1 של האשף = פאנל-בחירת-המבחנים הקיים (re-use, לא לשכתב). ב-STATE B האשף לא מוצג; במקומו כפתור "כוונן מחדש" בתוך ה-Disclosure שפותח את האשף עם התשובות השמורות.

**4 הצעדים:**

1. **אילו מבחנים** — `pickExamsPanel` הקיים כמו-שהוא (בחירה + טוגל A/B + תג "מומלץ"). כפתור "הבא".
2. **סגנון-הכנה** — שאלה יחידה, 3 כפתורי-רדיו גדולים:
   - `steady` — "קצת כל יום" (ברירת-מחדל, מומלץ) → פיזור מלא על החלון.
   - `crammer` — "בעיקר בימים שלפני" → מכווץ את החלון ל-~10 ימים אחרונים לכל מבחן.
   - `light` — "כבר התחלתי, רק לחזור" → מוריד תקציב-שעות ב-25%.
3. **ימים חסומים** — "יש ימים שבהם *אי-אפשר* ללמוד? (עבודה, מילואים, אירוע)". בורר-תאריכים מרובה (chips של תאריכים נבחרים). זה בדיוק מזין את `unavailable[]` שכבר קיים במנוע וב-tRPC אך אף UI לא ממלא אותו היום. **הבהרה ליד השדה:** "לא נחסום לך שום מוֹעד — רק נמנע מלשבץ לימוד ביום הזה."
4. **סקירה + בנייה** — `StudySkyline` preview חי + `recsCard`, וכפתור "בנה לי תוכנית" (ה-`handleGenerate` הקיים, עם התוספות למטה).

**מצב (state) חדש בקומפוננטה:**
```ts
type PrepStyle = "steady" | "crammer" | "light";
const [step, setStep] = useState(1);              // 1..4
const [prepStyle, setPrepStyle] = useState<PrepStyle>("steady");
const [blockedDays, setBlockedDays] = useState<string[]>([]); // "YYYY-MM-DD"
```

**Cold-start / empty:** אם אין קורסים בתוכנית → צעד 1 מציג את ה-empty-state הקיים ("עוד אין תכנית לימודים... לבניית התכנית") ומדלג על 2-4. אם יש קורסים אבל אין מבחנים קרובים → הודעה קיימת. אם המשתמש דילג על 2-3 (לחץ "בנה" מוקדם) → ברירות-מחדל `steady` + `blockedDays=[]`.

**מובייל:** צעד אחד במסך, פס-התקדמות דק למעלה (4 נקודות), כפתורי "הבא/חזרה" דביקים בתחתית. הבורר-תאריכים = `<input type="date">` + "הוסף" שמוסיף chip (לא date-picker כבד).

## 3. שינויי-מנוע — להזין את תשובות-האשף (`exam-planner.ts`)

הרחבת `generateExamPlan` בפרמטר-אופציות (backward-compatible — קריאות קיימות לא נשברות):

```ts
export interface PlanOptions {
  prepStyle?: "steady" | "crammer" | "light"; // default "steady"
  unavailable?: string[];                      // כבר קיים כפרמטר נפרד — לאחד לכאן
}
export function generateExamPlan(exams, now = new Date(), opts: PlanOptions = {}): ExamPlanResult
```

**התנהגות לפי `prepStyle`:**
- `steady` — ההתנהגות הנוכחית (חלון 21 יום, פיזור nearest-first).
- `crammer` — צמצם את חלון-האיסוף מ-21 ל-**10** (`const WINDOW = prepStyle === "crammer" ? 10 : 21;`). התקציב זהה → צפיפות גבוהה יותר סמוך למבחן. אחרי הבנייה, אם יום עובר 6 ש' → הוסף `clash`-like rec ("היום X עמוס — 6+ שעות").
- `light` — `totalHours = Math.round(totalHours * 0.75)` (ואז `sessionCount` נגזר מזה). מינימום 2 sessions נשמר.

**חשוב:** `analyzeExamPeriod` צריך לקבל גם הוא את `prepStyle` כדי שה-deferB יתחשב בעומס האמיתי. הוסף המלצה חדשה `kind:"heavyDay"` כשקיים יום ≥6 ש' (טקסט: "יום Y מרוכז מדי — שקול לפרוס אותו").

**tRPC:** `study-task.ts` → `generateExamPlan` — הוסף לקלט:
```ts
prepStyle: z.enum(["steady","crammer","light"]).optional(),
// unavailable כבר קיים
```
והעבר ל-`generateExamPlan(examInputs, new Date(), { prepStyle: input.prepStyle, unavailable: input.unavailable ?? [] })`.

**שמירת התשובות (כדי ש-"כוונן מחדש" ב-STATE B יזכור):** אל תוסיפו טבלה. שמרו `prepStyle` ו-`blockedDays` בשורת-ה-exam הראשונה בשדה `notes` כ-suffix מוסתר, למשל `[auto] high [ps:crammer] [bd:2026-07-12,2026-07-14]`, ו-`plan-from-tasks.ts` יחלץ אותם (regex) כדי לאתחל את האשף. זה עולה בקנה אחד עם דפוס ה-`[auto]` הקיים ולא דורש מיגרציה. (חלופה: `localStorage` — פשוט יותר אך לא עובר-מכשירים. **המלצה: notes-suffix**, כי התוכנית כבר חיה ב-DB וזה נשאר עקבי.)

## 4. ייצוא איכותי — Excel אמיתי + gantt חזותי (#15, #34)

היום: CSV שטוח + ICS. הבקשה: "Excel/gantt אמיתי". שלוש שכבות, בסדר-עדיפות:

### 4a. Excel רב-גיליוני עם צבע (עדיפות ראשונה)
**קובץ חדש:** `src/lib/xlsx-export.ts`. השתמש ב-**`exceljs`** (כבר תומך בעברית RTL, מילוי-תא צבעוני, רוחב-עמודות; ~מותקן? אם לא — `npm i exceljs`). **המלצה: exceljs** על-פני `xlsx`/SheetJS כי SheetJS-הקהילתי לא כותב צבעים בקלות ו-exceljs נותן גם RTL sheet-view.

שני גיליונות:
- **"תוכנית" (Plan)** — RTL sheet (`worksheet.views=[{rightToLeft:true}]`). עמודות: תאריך · יום · קורס · סוג · פירוט · שעות. כל שורה נצבעת ב-`fgColor` = `task.color` (מומר ל-ARGB, ~15% opacity לרקע-תא). שורות-מבחן בולד + רקע אדום-בהיר. שורת-סיכום-יום כל יום עם סך-שעות.
- **"ציר-זמן" (Gantt)** — grid יום×קורס: עמודה לכל יום (מהיום עד המבחן האחרון), שורה לכל קורס. תא מלא בצבע-הקורס אם יש session באותו יום (עוצמת-הצבע ∝ שעות: fill מלא ל-≥5 ש', חצי לפחות). תאי-מבחן = "A"/"B" ברקע אדום. זהו ה-gantt ה"אמיתי" שהטקסט-CSV לא יכול לתת.

פונקציה: `downloadStudyPlanXlsx(tasks: GanttTask[], isHe: boolean)`. ה-`toGantt()` הקיים ב-content כבר בונה את המבנה — פשוט מזרימים אליו.

### 4b. תצוגה-מקדימה-להדפסה (fallback נקי, אם לא רוצים תלות)
אם אריאל מעדיף אפס-תלויות: `window.print()` על view ייעודי `#print-plan` עם `@media print` שמסתיר את ה-chrome ומראה skyline+agenda נקיים. מהיר, אך פחות "Excel". **המלצה: לבנות את 4a; 4b כתוספת-`print` זולה.**

### 4c. ICS — נשאר, מתוקן
`exportIcs` הקיים תקין. תוספת קטנה: הוסף `DTSTAMP` ו-`BEGIN:VALARM` (תזכורת יום-לפני) לכל session, כי גוגל-קלנדר מציג טוב יותר. שמור על ה-UID הקיים.

### שדרוג ה-ShareMenu (#34 — "שיתוף עושה בלגן")
`ShareMenu` הנוכחי טוב (Radix portal). שנה את התוכן ל-4 פריטים ברורים, מסודרים לפי "כמה שימושי":
1. **הוסיפו ליומן Google** (ICS) — ראשי.
2. **הורדת Excel צבעוני** (4a) — חדש, בולט.
3. **הורדת טבלה (CSV)** — משני (קיים).
4. **הדפסה / PDF** (`window.print`) — משני.

הסר את תחושת-הבלגן: כל פריט עם אייקון + שורת-מיקרו-קופי אחת ("נפתח ב-Excel עם צבעים"). רוחב תפריט `w-64`. **בטל את כל קוד-השיתוף הישן שאולי נשאר** (חיפוש `navigator.share`/`.xls` — אם קיים, למחוק; ה-`.xls`-כ-HTML כבר הוחלף לפי הערת-הקובץ ב-excel-export.ts).

## 5. תיקון ה-gantt החלש בטאב-היומן (#38)

**היכן:** `ExamGantt` (`exam-gantt.tsx`), מוצג דרך `/calendar` → "מבחנים" → `ExamSchedule` → תת-טאב "ציר-זמן".

**הבעיה:** טבלת יום×קורס ריקה-ברובה — הרבה עמודות-יום ריקות, תאי A/B זעירים, בלי מידע-עומס. "חלש" = לא אומר כלום שה-List לא אומר.

**ההחלטה (המלצה חדה):** **אל תתחזקו שני גרפים.** החליפו את תוכן תת-הטאב "ציר-זמן" ב-`ExamSchedule` מ-`ExamGantt` ל-**`StudySkyline`** — הגרף הטוב שכבר קיים ומתוחזק. זה מאחד את שפת-העיצוב, נותן verdict-rail + עומס-צבעוני במקום טבלה ריקה, ומסיר קוד-כפול.

**איך:** ב-`exam-schedule.tsx`:
- החלף `import { ExamGantt }` ב-`import { StudySkyline }` + `import { buildSkylineModel }`/`generateExamPlan`/`analyzeExamPeriod`.
- בנה `ExamPlanResult` מ-`ganttCourses` הקיים: לכל קורס-עתידי צור `ExamInput` (מוֹעד = A אם קיים ועתידי, אחרת B), הרץ `generateExamPlan` → `plan`, `analyzeExamPeriod(plan,isHe)` → recs. שים לב: כאן אין בחירת-מוֹעד של המשתמש, אז הראה **את שני המועדים כפנאנטים** (skyline כבר מצייר פנאנט לכל exam ב-`examsByDay`). כדי שגם A וגם B יופיעו — צור שני `ExamInput` לקורס עם שני מועדים (אחד `moed:"A"` ואחד `"B"`), או פשוט העבר את `plan.exams` עם שתי רשומות. (זהו view לקריאה-בלבד; אין persistence.)
- `<StudySkyline plan={plan} recommendations={recs} isHe={isHe} />` (בלי `onDayClick` — read-only).
- מחק את `import`+שימוש `ExamGantt` מ-`exam-schedule.tsx`.

**מה עם `ExamGantt` בטופס-האונבורדינג?** (`semester-planner/index.tsx:751`) — שם הוא מציג *מועדי-מבחן של קורסים-מתוכננים בלי לימוד* (אין עדיין study-tasks). שם ה-skyline לא מתאים (אין sessions). **החלטה:** השאר את `ExamGantt` באונבורדינג בלבד, אך שדרג-מינימלית: (א) הסתר עמודות-יום ריקות רצופות (collapse של ≥4 ימים ל-"N ימים" כמו ב-skyline), (ב) הגדל תאי A/B ל-min-w קריא, (ג) הוסף שורת-verdict אחת מעל ("המבחן הראשון בעוד X ימים · המרווח ההדוק ביותר Y ימים"). זה מרפא את "החולשה" גם שם בלי למחוק.

**חלופה שנדחית:** לתחזק gantt נפרד ומשוכלל — נדחה, כי #38 הוא בדיוק "יש שני גרפים ואחד חלש". איחוד עדיף.

## 6. #32 — בחירת מוֹעד א'/ב' בלי לנחש (בטיחות)

הלוגיקה כבר בטוחה (`recommendMoed` = ברירת-מחדל A, B רק בצפיפות). מה שחסר זה **שקיפות** כדי שהסטודנט יבין *למה*, בלי שהאפליקציה תתחזה ליודעת-תאריכים-עתידיים.

> - **אנחנו לא יודעים מראש כמה קשה יהיה כל מוֹעד ולא ננחש תאריכים שלא פורסמו.** ההמלצה כאן היא לפי מרווח ועומס בלבד.

## 7. אינטראקטיביות נוספת ב-Agenda (#37) — כפתורי-כוונון

ה-`Agenda` כבר תומך done / +1 / מחיקה / "דחו יום" / "+לימוד". הוסף שני כפתורי-כוונון שחסרים כדי לענות במלואו על "shift a study block, add a break, push a day":

1. **"הוסף הפסקה"** (add a break) — chip ברמת-היום ליד "+לימוד". בלחיצה: יוצר `StudyTask` מסוג `custom` בכותרת "מנוחה / הפסקה", `notes` ריק (לא `[auto]` → שורד רענון), 0 שעות. בסקייליין לא מצויר (אין hours), ב-agenda מופיע כשורה עם אייקון `Coffee`. תכליתו הצהרתית: מאותת "ביום הזה בכוונה לא לומדים".
2. **הזזת-בלוק בין-ימים** (shift a study block) — ה-+1 הקיים דוחה יום-אחד. הוסף גם **-1** (משוך יום קדימה) לצד ה-+1, עם אותו `updateMutation` (הגבל: לא לפני היום, לא אחרי המבחן של אותו קורס). זהו ה-"shift" המבוקש, בלי drag-and-drop (מובייל-בטוח).

**אל תוסיפו drag-and-drop** — במובייל-RTL זו מלכודת. כפתורי ±1 + push-day + quick-add נותנים את כל הכוונון הדרוש.

## 8. Edge cases (חובה לטפל)

- **מבחן היום/עבר:** המנוע כבר מסנן `_date > today`. ה-adapter מסנן exam-tasks עתידיים בלבד. שמור.
- **חלון ריק (מבחן מחר):** `available.length===0` → המנוע מדלג על המבחן. באשף צעד-4, אם *כל* המבחנים מחר → הראה "המבחנים קרובים מדי לתכנון-לאחור — מציגים אותם בלוח בלי שיבוץ-לימוד."
- **prepStyle=light עם קורס-קל:** `totalHours*0.75` עלול לרדת מתחת ל-`SESSION_HOURS` → `Math.max(SESSION_HOURS, ...)` שומר מינימום. ודא 2 sessions מינימום נשמר.
- **blockedDays חוסם את *כל* החלון:** אם כל 21/10 הימים חסומים → `available=[]` → מדלג; הראה rec "חסמת את כל הימים לפני מבחן X — פנה יום אחד לפחות."
- **חסימת-יום-של-מבחן:** למשתמש אסור לחסום יום שבו יש מבחן (חסר-משמעות). סנן בורר-התאריכים: אל תאפשר להוסיף chip של תאריך-מבחן.
- **exceljs לא זמין:** אם מחליטים לא להתקין — ShareMenu מסתיר את פריט-Excel (feature-flag פשוט) ומשאיר CSV+ICS+Print. אל תשבור build.
- **RTL ב-Excel:** בלי `rightToLeft:true` העמודות יופיעו הפוך לעברית. חובה.
- **גופן-רצפה:** כל טקסט-עברית באשף ≥12px (הכרטיסים והשאלות — לא `text-[11px]` על משפטים).

## 2. The missing life-state: introduce "בלימוד / In progress" as a *derived, non-destructive* status

This is the single highest-leverage change and it makes #4, #22 cohere.

**Decision (recommended):** Do **not** mutate the DB to flip courses to IN_PROGRESS. Instead **derive** "currently studying" at read time from the academic calendar, exactly like the app already derives the current year (`deriveYearOfStudy`) and the wrap target (`getWrapTarget`). A PLANNED course whose `plannedYear === currentYear` and `plannedSemester === acadNow.semester` **and** the calendar phase is `teaching`/`exams` is displayed as **"בלימוד"** — a purely visual overlay. *Why:* zero migration, no data-loss risk, survives semester rollover automatically, and can never corrupt the plan the way a stored bump would (the same reasoning the codebase already used to kill the "advance semester" button in `semester-wrap-card.tsx`).

**New pure helper** — add to `src/lib/semester-clock.ts` (it already imports `getAcademicNow`):

```ts
/** Is this planned course the student's live, currently-being-studied course? */
export function isCurrentlyStudying(
  course: { plannedYear: number; plannedSemester: string; status: string },
  currentYear: number,
  now: Date = new Date(),
): boolean {
  const a = getAcademicNow(now);
  if (a.isStale) return false;
  if (a.phase !== "teaching" && a.phase !== "exams") return false;
  return (
    course.status === "PLANNED" &&
    course.plannedYear === currentYear &&
    course.plannedSemester === a.semester
  );
}
```

**Where it shows (three surfaces, one label "בלימוד"):**
- **Planner `course-card.tsx`** — `STATUS_ICON` already has an `IN_PROGRESS` blue `BookOpen`. Render that icon + the label `t("IN_PROGRESS")` when `isCurrentlyStudying(...)` is true, even though the stored status is PLANNED. The mark-complete popover stays.
- **Home `MyStatusHero`** — add a thin line under the hero total: `"X קורסים בלימוד עכשיו"` linking to `/record?scan=1` (see §3).
- **Record** — currently shows **only** COMPLETED. Add a collapsed-by-default section at the top: **"בלימוד עכשיו ({n})"** listing the derived in-progress courses, each with a one-tap "סמנו כהושלם + ציון" that opens the same inline `GradeInput`. This is the answer to "the app should *ask* me" — the ask lives where completions live.
