## חלק 0 — פרוטוקול העבודה (לקרוא בכל סשן, לפני הכול)

### 0.1 כללי ברזל של הסביבה
- `git` ממופה ל־`true` בשל־זה: **תמיד `command git`**. אחרי push לוודא `command git rev-parse HEAD` == `origin/main`.
- פריסה: `npx vercel --prod --yes`. אם חוזר "Not authorized" — לנסות שוב פעם אחת (זה חולף). לוודא Ready ב־`npx vercel ls --prod` + עמוד `/he` מחזיר 200.
- מסד־נתונים אחד = **פרודקשן** (Supabase). זהירות בכתיבות. מיגרציות: תוספות בלבד (additive), דרך `npx prisma migrate deploy --config prisma/prisma.config.ts`, **לפני** פריסת קוד שמשתמש בטבלה החדשה.
- חשבון הדמו (demo@pakamon.dev) הוא **קריאה־בלבד** (שומר ב־`src/server/trpc/init.ts`). בדיקות־דפדפן עושים דרכו; בדיקת מסלולי־כתיבה — רק ב־vitest או בחשבון־בדיקה אמיתי.
- בידינג: **לעולם לא לנבא נקודות מכרז.** מנגנון ובטיחות בלבד.
- Tailwind v4: `.data-card` בשכבת `pakam-ui`; אסור `@layer components`; אסור `*/` בתוך הערת CSS; מודאל שיש לאב שלו transform — לרנדר בפורטל.
- `GEMINI_MODEL` חייב להישאר מודל חינמי עדכני (כרגע gemini-2.5-flash-lite).
- אנגלית לא נספרת בממוצע התואר (אושר ע"י אריאל). `englishLevel` מוצהר גובר על ציון אמירם דרך `resolveEnglishLevel`.
- מונחים: ש״ס (בגרשיים), בלי נ"ז, "תחום מיקוד" (לא "התמחות"). קופי מוצר ברבים (אתם/שלכם); צ'אט היועץ וה־`pg()` המגדרי נשארים יחיד.

### 0.2 שער האיכות — לפני כל commit
1. `npx tsc --noEmit` נקי.
2. `npx vitest run` — כל הבדיקות (383+) ירוקות. פיצ'ר חדש = בדיקות חדשות.
3. אימות בדפדפן כמשתמש־דמו (ראו 0.3).
4. **סקירה־עצמית יריבה של הדיף** — לחפש במיוחד את שתי תבניות־הרגרסיה שכבר תפסו אותנו:
   - אפקט־סנכרון שמחזיר פריטים שהמשתמש הסיר (רגרסיית R3).
   - שינוי בלוגיקת כיווץ/דדופ שמשנה סמנטיקת "נצבר" (רגרסיית R5).
5. עדכון `docs/משימות-בקרה.md` + דיווח לאריאל בעברית פשוטה (רמת כיתה י"ב, בלי ניסוחי־AI).

### 0.3 אימות בדפדפן — איך עושים את זה נכון
- להרים שרת דרך `preview_start` (קונפיג `pakam-dev` קיים ב־`.claude/launch.json`).
- **לא לסמוך על צילומי־מסך למדידת פריסה** — כלי הצילום מצלם חלון מוקטן והכול נראה "דחוס". מודדים DOM: `getBoundingClientRect`, `getComputedStyle`, `preview_snapshot`.
- גלאי שבירות־עברית (להריץ על כל עמוד שנוגעים בו, כולל אחרי פתיחת תפריטים/דיאלוגים):

```js
(() => {
  const heb = /[֐-׿]/; const bad = [];
  for (const el of document.querySelectorAll('*')) {
    const t = [...el.childNodes].filter(n => n.nodeType === 3 && heb.test(n.textContent) && n.textContent.trim().length > 2);
    if (!t.length) continue;
    const cs = getComputedStyle(el);
    if (cs.direction === 'ltr' || cs.textAlign === 'left')
      bad.push({tag: el.tagName, txt: el.textContent.replace(/\s+/g,' ').trim().slice(0,42)});
  }
  return JSON.stringify({page: location.pathname, count: bad.length, samples: bad.slice(0,8)}, null, 1);
})()
```
- כלל־הזהב ל־RTL: **לעולם לא `dir="ltr"` על טקסט שמכיל מילה עברית.** מספרים/תאריכים/קודי־קורס מבודדים ב־`<bdi dir="ltr">` בלבד. (כך תוקן "X% נכשלים" בקטלוג ב־d127cec.)

### 0.4 משמעת ביצוע (זה מה שהופך אותך לפייבל)
- **פרוסה אחת בכל פעם.** לא פותחים שני פיצ'רים במקביל. מסיימים פרוסה = שער־איכות מלא + פריסה + עדכון מעקב.
- לפני כתיבת קוד: לקרוא **את כל** הקבצים שנוגעים בהם, מההתחלה לסוף. בלי הנחות מהזיכרון.
- כשיש ספק בין שתי דרכים — לבחור לפי קריטריוני־הקבלה שכאן, לא לפי טעם. אם קריטריון לא מכסה — לשאול את אריאל רק אם זו החלטת־בעלים (רשימה בחלק 5); אחרת להחליט לפי הפשוט־יותר ולתעד.
- דיווח כן: נכשל = אומרים נכשל עם הפלט. דילגנו = אומרים דילגנו.

## חלק 3 — שלב P: חוויית התכנון (ההערה הכי חשובה — 2/35/20)

**עקרון מנחה (הוחלט):** הגריד השבועי הופך ל**משטח הבחירה הראשי**. לא בוחרים קבוצה מרשימה ואז מסתכלים על לוח — בוחרים **על הלוח**.

### P1 — בחירת קבוצות על הגריד (ghost blocks)
**איפה:** `/planner/semester` (בניית המערכת). **מהות:** כשקורס בפוקוס (hover/קליק ברשימת הקורסים), כל הקבוצות החלופיות שלו מצטיירות על הגריד כבלוקים "רפאים" (שקופים־מקווקווים). קליק על בלוק־רפאים = בחירת הקבוצה (מתמלא). קבוצה שמתנגשת עם בלוק קיים — רפאים אדמדם + אייקון התנגשות. במובייל (375): הקשה על קורס פותחת sheet עם הגריד.
**קבלה:** בוחרים קבוצה לקורס בלי לגעת בשום dropdown; התנגשות נראית **לפני** הבחירה; עובד במקלדת (Tab/Enter); נשמר ל־`selectedGroups` הקיים; לא שובר את המסלול הישן (ה־dropdown נשאר כגיבוי); RTL נקי; 0 רגרסיות ב־vitest.
**מוקשים:** לא לגעת בסכמת `selectedGroups`; הדמו לא שומר — בדיקת שמירה ב־vitest על הראוטר.

### P2 — מנוע התנגשויות + הצעה חכמה
**מהות:** כפתור "מצאו לי שילוב בלי התנגשויות": חיפוש על צירופי הקבוצות (backtracking; דירוג = התנגשויות×1000 + ימים־בקמפוס×10 + מרווח־יומי־מרבי; חיתוך מוקדם, תקרת 10,000 צירופים). מציג את הפתרון על הגריד עם "החל/בטל".
**קבלה:** על נתוני הדמו מציע שילוב 0־התנגשויות בפחות משנייה; "בטל" מחזיר את המצב הקודם במדויק; בדיקות יחידה למנוע (3 תרחישים: פתיר, לא־פתיר, כבר־תקין).

### P3 — כיול מד־העומס מחדש (הערה 2, "רמת עומס ישנה")
**נוסחה (הוחלט):** `load = 0.5*שעות־שבועיות + 1.5*ימים־בקמפוס + 0.5*מתיחה־יומית־מרבית(שעות)`. ספים: קל <10, בינוני 10–16, כבד >16. להציג כצ'יפ 3־מצבים עם tooltip פירוט ("14 שעות, 4 ימים, מתיחה 8:00–16:00").
**צעדים:** לקרוא קודם את `workload-calculator.ts` הקיים ולעדכן/להחליף; לעדכן בדיקות.
**קבלה:** המד מגיב חי לשינוי בחירת קבוצות; הפירוט תואם למציאות; בדיקות יחידה לנוסחה.

### P4 — מודעות לסוג הסמסטר (הערה 35)
**מהות:** אם >70% מש״ס הסמסטר הם חובה (שנה א׳ טיפוסית) — ברירת־המחדל היא "המערכת המומלצת" מוכנה עם כפתור אישור אחד + אפשרות עריכה. אם בחירה־כבדה — נפתח ישר מצב הבנייה.

## חלק 4 — שלב E: תקופת המבחנים (הערות 15/32/34/37/38)

### E1 — שאלון פתיחה קצר

### E2 — גאנט אינטראקטיבי
**מהות:** תצוגת ימים (שורה=יום, מהיום עד המבחן האחרון), בלוקי־לימוד צבועים לפי קורס, מבחנים כעוגנים בולטים. גרירת בלוק ליום אחר (dnd-kit כבר בפרויקט — אותה תבנית כמו YearBoard כולל KeyboardSensor), הקשה = הקטנה/הגדלה/מחיקה. נשמר מיידית.

**מהות:** ליד כל מבחן מציגים את שני התאריכים (אם קיימים בקטלוג). ברירת־מחדל: מועד א׳, עם שורת הסבר "רוב הסטודנטים ניגשים למועד א׳; מועד ב׳ — {תאריך}". מילואימניק (קבוצת מילואים פעילה): להזכיר את זכאות 2־מתוך־3. אם תאריך חסר — לכתוב "התאריך טרם פורסם" — **לעולם לא להמציא תאריך**.
**קבלה:** כל מבחן מציג מקור־אמת; אפס תאריכים מומצאים (בדיקה: קורס בלי examDateB).

### E4 — תיקון שיתוף/ייצוא (הערה 34)
**אבחנה צפויה:** תפריט השיתוף נחתך — כנראה ה־gotcha של transform על אב (ראו 0.1) → לרנדר בפורטל (Radix DropdownMenu כבר עושה זאת; אם זה רכיב ידני — להחליף ל־Radix). ייצוא אקסל: גיליון גאנט — שורה=יום, עמודה=קורס, תא צבוע לפי הקצאה (יש `excel-export.ts` עם צבעים).
**קבלה:** התפריט נראה במלואו ב־375; הקובץ נפתח באקסל עם צבעים; וואטסאפ משתף תקציר יומי קריא.

### E5 — הסרת הגאנט החלש מהיומן (הערה 38) — הכרעה מומלצת
**החלטה:** גאנט טוב אחד (ב־exam-planner) עדיף על שניים בינוניים. מטאב היומן מסירים את תצוגת־הגאנט החלשה; היומן נשאר: גריד שבועי + רשימת בחינות + קישור "לתכנון מלא". **וטו לאריאל:** אם תרצה לשמר — אמור, וזה יישאר.
**קבלה:** אין כפילות קורסים ביומן (הבאג "מבוא ללוגיקה פעמיים" תוקן — לוודא שנשאר); הקישור מוביל לגאנט החדש.

## חלק 5 — שלב S: השכבה החברתית (הערות 3/16)

**קונספט (הוחלט): "חוכמת המחזור"** — לא פיד ולא צ'אט. שלושה משטחים על תשתית קיימת (`CourseGradePoint`, `CourseReview`, ראוטר course-knowledge, `ReviewReport` — הכול כבר במסד):

### S1 — זרימת תרומה
אחרי נעילת ציון (commitGrade) מציעים: "רוצים לעזור למחזור? 10 שניות" → שני מחוונים (קושי 1–5, שווה־את־זה 1–5) + שורה חופשית אופציונלית. תמיד ניתן לדלג.
**קבלה:** התרומה נשמרת אנונימית; אין דרך לקשר שם לתרומה ב־UI או ב־API; מופיע רק אחרי ציון אמיתי (אנטי־זבל בסיסי); בדיקות ראוטר.

### S2 — הצגה בקטלוג
בשורת קורס + בפאנל הפרטים: "המחזור: ממוצע {X} · קושי {Y}/5 · {n} מדרגים" + עד 3 ציטוטים קצרים. **כלל פרטיות קשיח: לא מציגים כלום מתחת ל־n=3.** לצד נתוני האוניברסיטה עם תיוג מקור כן (יש `gradeDataSource`).
**קבלה:** קורס עם n<3 לא מציג כלום; המקורות מתויגים; כפתור דיווח מחובר ל־`ReviewReport`.

### S3 — המלצות במתכנן
בבחירת קורסי־בחירה (P1): תג "מומלץ ע"י המחזור" לקורסים עם shove-את-זה ≥4 ו־n≥3, ומיון "לפי המלצות המחזור".
**קבלה:** התג מופיע רק בתנאים; המיון עובד; אפס האטה מורגשת (שאילתה מצטברת, לא N+1).

### S4 — "תיק מחזור" (עמוד מרוכז) — **שער־בעלים.** לתכנן מפרט קצר ולהציג לאריאל לפני בנייה.

## חלק 6 — שלב SC: הסורק (הערות 24/25/26/31) — נפתח רק כשאריאל שולח PDF

**עד אז לא לגעת בפרסור.** כשמגיע הקובץ:
1. **לא לשמור את ה־PDF בריפו** (פרטי!). לחלץ ממנו fixture אנונימי (JSON של שורות) לתיקיית הבדיקות.
2. בדיקות fixture: כל סוג שורה — ציון מספרי, פטור, עבר, נכשל, בינארי, שורת רמת־אנגלית, שורות סיכום, ריבוי סמסטרים. **קבלה: 100% מהשורות מסווגות נכון, אפס ציונים מומצאים.**
3. שברי־מילים ("ש׳") = כמעט בוודאות היפוך bidi בחילוץ הטקסט מה־PDF — לנרמל את כיוון הטקסט לפני הפרסינג ולכסות בבדיקה.
4. העלאה חוזרת (כל סמסטר): התאמה לפי קוד־קורס; מסך דיפ "מה השתנה מהגיליון" — עדכון ציון קיים רק באישור פר־שורה. שום מחיקה אוטומטית.
5. הכוונה: בפתיח הסורק להוסיף "איפה משיגים את הקובץ": מידע אישי ← גיליון ציונים ← הורדה כ־PDF (לאמת מול myTAU לפני כתיבה).
6. הצטיינות/כישלון (הערה 25): כישלון מיובא כ־FAILED (לא נספר); הצטיינות — אין שדה ייעודי; אם אריאל ירצה תג הצטיינות → שער־בעלים.
