# פכמון — תוכנית-אב להשקה (נכון ל-28.6.2026)

מסמך-העל לקראת השקה אמיתית. נכתב אחרי בדיקת-משתמש של אריאל, מימוש 3 ימי-עבודה,
ואודיט-עומק מ-6 כיוונים (RTL, באגים, סילבוסים, ממשקים, שכפול-תארים, ליטוש-UX).
מלווה את המסמך התפעולי [תוכנית-המשך.md](תוכנית-המשך.md) ואת מסמך-האמת לחוקים

## חלק א׳ — איפה אנחנו עכשיו (מצב אמת)

האפליקציה חיה (https://pakam-strategist.vercel.app), עברה מ-NO-GO 52 ל-GO רך,
112 בדיקות עוברות, tsc נקי, build עובר.

**מה נבנה ב-3 הימים האחרונים (ואומת חי):**
1. **מנוע המלצות חכמות** — דטרמיניסטי, מבוסס-נתונים אמיתיים: מועד ב׳ עם תאריך,
   דרישות חסרות, אנגלית, התמחות, סמינר, שיפור-ציון, אזהרת-סף-מעבר. בולט בראש הדשבורד.
2. **ממוצע כללי בולט** ב-ScoreDisplay.
3. **תיקון באג הסיור** — `.data-card` (CSS לא-ב-layer) דרס את `fixed` של Tailwind v4
   והמודאל נפתח ~5,700px מתחת למסך. תוקן + פתיחה-אוטומטית עמידה בפני localStorage תקוע.
4. **מילואים לעומק** — תווית-מילואים קבועה בכל עמוד (קבוצה + "ההטבות שלי" עם כל
   ההטבות, מכסות, אזהרת 25%).
5. **סימון בינארי פר-קורס** — שדה `isBinary` (migration בפרודקשן), טוגל בכרטיס,
   החרגה מהממוצע, אזהרות. כולל תיקון 3 מקרי-קצה (ביטול-השלמה מאפס בינארי, טוגל רק
   עם ציון, סנכרון מכסה).
6. **תיקון RTL מקיף** — עוזר `Bidi` ([src/lib/bidi.tsx](../src/lib/bidi.tsx)) שמבודד
   ריצות-LTR (35+, 21-34, +10%, קודים, תאריכים). אומת ברמת-תו שהמספרים מתרנדרים נכון.

## חלק ב׳ — ניסוי-המחשבה: הישיבה עם נשיא TAU

תרחיש: אריאל מציע את הפלטפורמה כעסק — פכ"מ + 4 תארים נוספים. בחדר: הנשיא, 4
תלמידים נבחרים, בכירים, אחראי-דאטה, ומועצת-התלמידים. מה כל אחד שואל, אוהב, ומחפש.

### מה הם **יאהבו** (נקודות-החוזק שלנו)
- **המנוע הדטרמיניסטי, לא "AI שממציא".** כל מספר נשען על מקור (ידיעון/ערזים/חוק).
  זה בדיוק מה שאחראי-דאטה ונשיא רוצים לשמוע — אפס הזיות, מקור לכל נתון.
- **סנכרון אוטומטי יומי מהידיעון** (cron 03:00) עם מנוע-diff שמזהה שינויי אמצע-סמסטר
  (מרצה/חדר/מועדים) ומחיל אוטומטית, ושינויים "כבדים" עוברים אישור-אדמין. → תשובה
  ניצחת ל"איך הנתונים נשארים עדכניים".
- **חוקי-הפכ"מ והמילואים מקודדים במקור-אמת אחד** (MILUIM_CONFIG + ProgramDefinition),
  עם בדיקות-יחידה. אמין ל-benchmark.
- **ארכיטקטורת רב-תוכנית אמיתית** — תואר משפטים כבר מוגדר מלא (141 ש"ס, 7 דיסציפלינות).
  זה ההוכחה לנשיא שזה לא "אפליקציה לפכ"מ" אלא **תשתית לכל תואר**.
- **דשבורד ומתכנן מלוטשים** — מרשימים בדמו.

### מה הם **ישאלו**, ומה **חסר** (הפערים — ביושר)

### מה **מועצת-התלמידים** תשאל
- "האם זה רשמי? מי אחראי שהחוקים נכונים?" → צריך הסכמה מול הפקולטה + תווית "לא רשמי,
  עזר-החלטה בלבד" (כבר קיימת חלקית).
- "מה עם נגישות?" → RTL תוקן; צריך בדיקת-נגישות (קונטרסט, מקלדת, screen-reader).
- "פרטיות הנתונים שלנו?" → יש מדיניות-פרטיות; הדמו קריאה-בלבד; להבהיר היכן נשמר מה.

## חלק ג׳ — סדר-עדיפויות להשקה (לפי ROI לפיץ׳)

**גל 1 — "מוכן להראות לנשיא" (1-2 שבועות):**
1. **שכפול תואר שני (משפטים) end-to-end** — בחירת-תוכנית באונבורדינג + ניקוי קבועים.
   זה ההוכחה ל"פלטפורמה", לא "אפליקציה". (סעיף 1)
2. **סילבוס → מטלות אוטומטיות** — הפיצ׳ר שהכי "מרשים" בדמו. (סעיף 6)
3. **ליטוש 3 המסכים הקלאנקיים** (תקנון, קטלוג, תיק). (סעיף 3)
4. **RTL רוחבי** — להחיל `Bidi` בכל המסכים. (סעיף 2)

**גל 2 — "מוצר אמיתי" (אחרי פיילוט):**
5. סנכרון מועדי-בחינה ליומן + מייל מוסדי (Gmail readonly). (סעיף 4)
6. חשיפת "מקור + עדכניות" פר-נתון. (סעיפים 8-9)
7. מעקב-בידינג ידני + התראות. (סעיף 4)

**גל 3 — "קנה-מידה":**
8. הוספת 3 התארים הנוספים (1-2 ימים/תואר אחרי שהאינטגרציה מוכנה).
9. נגישות מלאה + בדיקת-עומס.

## חלק ד׳ — הערות טכניות (ממשיכים מ-[תוכנית-המשך.md](תוכנית-המשך.md))
- **git שבור**: alias ל-`true` → להשתמש ב-`/usr/bin/git`. דחיפה מתנתקת → retry + low-speed flags.
- **deploy**: `npx vercel --prod --yes` (נחסם אוטומטית ב-harness — דורש אישור-משתמש מפורש).
- **migration לפרודקשן**: הדרך הבטוחה = `npx tsx prisma/apply-migration.ts <dir>` (טרנזקציה,
  אידמפוטנטי, לא reset). נבנה בסבב הזה. `prisma migrate dev` מסוכן מול Supabase (shadow DB).
- **RTL**: כל טקסט עברי עם מספר/טווח/+/% → לעטוף ב-`<Bidi text={...}/>`. אומת ברמת-תו.
- **מסד יחיד = פרודקשן** (Supabase). הדמו קריאה-בלבד (כל mutation נחסם בצד-שרת).
- **בדיקת-משתמש מאפס**: `npx tsx prisma/reset-test-user.ts <email>` → רענון → הרשמה מאפס.
